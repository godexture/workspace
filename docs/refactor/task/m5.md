# M5: runtime、ownership、旧 contract 層の切断

M5 全体の実装指示書。この文書は作業順と M5 で確定する設計判断を記録し、完了条件は
[runtime.md](../runtime.md#m5-完了条件)、削除・隔離範囲は
[inventory.md](../inventory.md#m5-の切断) を正本とする。

> 状態: **完了（2026-08-08）**。各作業単位を順に適用し、M5-4 の paired benchmark を確定してから M5-5 の cut を行った。

## 目的

M4 の private `Program` を、typed item を `any`、reflection、component lookup へ戻さずに実行する。
同期的な linear Processor は一つの island へ fuse し、queue、fan-out/fan-in、I/O の境界だけを
task 境界にする。ownership、cancel、EOF、Finalize、transaction、cleanup、observation を一つの
failure-safe lifecycle に統合し、旧 runtime との同一 process paired benchmark を取った直後に
旧 contract 層を repository の compile 対象から切断する。

M5 は実 WAVE/MP3/FLAC、一般向け変換 API、CLI、WASM、demo web を完成させない。実 codec の
最初の consumer は M4 の `plugin/pcm/linear` と walking skeleton とし、M6 以降が algorithm と
surface を新 contract へ順に接続する。

## 監査で確定した判断

### typed execution binding

- `schema.Descriptor.NewPipe/NewTee` と exported `schema.Queue/Fanout` は削除する。これらは M3 で
  typed closure が erased descriptor まで届くことだけを実証した仮 product であり、limit、cancel、
  ownership、close を持つ実 edge contract へ拡張すると schema package が scheduler を所有する。
- payload 型 `T` を知る `flow` の source/processor/sink shape helper が、operator assertion、schema
  traits、typed delivery closure を一度だけ捕捉する。plugin author が実装する contract は引き続き
  `Reader[T]`、`Processor[I,O]`、`Writer[T]`、`Operator` であり、channel、queue、goroutine、scheduler
  を受け取らない。
- private `Program` は graph topology、compile 済み operator factory、typed execution binding を
  dense node/edge に特殊化する。item loop では schema/component/config/policy/catalog を検索しない。
- `Processor` と `Writer` は move-on-success、caller-retains-on-error に統一する。既定 runtime は
  contract 検査用 state を item に持たず、instrumented schema traits と adversarial operator を使う
  conformance test が double take、成功時未消費、error 時消費、use-after-move を検出する。

### island、queue、fan-out/fan-in

- source、sink、同期一入力一出力 Processor、homogeneous many-input Processor の execution binding
  を別物として宣言する。Shape と opened operator の typed contract が一致しない場合は Open phase
  の plugin bug として node/component/phase を付けて拒否する。
- maximal linear Processor chain を一つの island にする。source I/O、sink I/O、fan-out/fan-in、
  explicit buffer、異なる rate/parallelism の境界だけに edge task を置く。node 数を goroutine/channel
  数へ写像しない。
- queue は `internal/run` が所有する typed bounded ring とし、items/bytes/time の `Limit`、context
  cancellation、idempotent close、drain/drop を持つ。bytes/time limit は captured `Size`/`Time` trait
  がある時だけ構築できる。item ごとの Host manager 呼び出しは行わず、edge-local state に蓄積する。
- linear delivery は `Fork` を呼ばない。fan-out binding は error 時の caller-retains 契約を守るため元 owner を
  rollback owner として保持し、各 branch の owner だけを retain する。部分失敗時は失敗・未配送 branch を drop
  して元 owner を caller に残し、全 branch 成功時に元 owner を drop する。one-output fan-out は通常の move と
  同じ経路へ簡約する。
- many input port は fan-in policy を必須とする。M5 runtime の実 consumer は deterministic zip/
  lockstep とし、connection order、buffering、watermark を Plan に固定する。他 policy も stable enum と
  validation を持つが、実 component が現れる milestone まで実行可能であると偽らない。

### allocator と host service

- payload allocation は `media/buffer.Allocator` の Job/component-local grant に属する。process global
  cache と `sync.Pool` は使わない。Host は Prepare/Open で粗粒度 grant を予約し、operator は
  `OpenContext.Buffers` から得た local allocator/function を保持する。
- ordinary allocation は zeroed memory を返す。`Overwrite` は mutable write lease だけを返し、
  Fill 成功後の Commit まで `Handle`/`View` を作れない。error/cancel/未 Commit lease は discard し、
  retained/in-use bytes は allocator owner へ一度だけ返す。
- `OpenContext` は Buffers、tracked Tasks、structured Events と当該 boundary resource だけを渡す。
  catalog や任意 service を引ける locator は作らない。plugin task は Host task group へ登録され、
  cancel、panic recovery、join、join timeout diagnostic の対象になる。

### lifecycle と result

- public lifecycle は `Host.Prepare` / prepared `Plan` / `Run` / `Close` と `Host.Run` convenience にする。
  `Host.Plan` は output transaction/operator を開かない read-only path のまま保つ。
- Run Open は output boundary transaction、Endpoint、通常 operator、Host task の順に登録し、途中失敗は
  task cancel/join を含めて逆順 rollback する。Job の owned direct resource も同じ scope が一度だけ閉じる。
- EOF は source `io.EOF` を edge close へ変換し、close が downstream Processor の `Flush` を依存順に
  一度だけ呼ぶ。success path は `Finalize -> Flush -> Sync -> PrepareCommit -> Commit`、failure/cancel は
  未 commit transaction の `Abort` を全件試行する。
- `Result` は primary failure、cleanup failures、phase-aware diagnostics、output ごとの committed/aborted/
  unknown/rollback-attempted outcome を別 field に持つ。cleanup は cancel 済み Run context ではなく
  Host policy の bounded cleanup context で行い、一つの failure で残りの cleanup を飛ばさない。
- panic recovery は island/task top に一度だけ置き、item loopに `defer` を置かない。observation off は
  no-op strategy を Open 時に選び、metric atomic、clock read、Size/Time trait 呼び出しを追加しない。

### direct resource と boundary

- reference Provider/Endpoint は M4 の private boundary state を OpenContext へ渡す。output boundary
  operator が transaction interface を実装し、Host が commit coordinator として所有する。
- direct Source/Sink は raw Go 型だけから media schema/component を推測しない。Job choice は resource と
  adaptor component/config を一緒に指定し、binder が通常 boundary と同じ shape validation を通す。
  これにより custom storage のための Provider 登録は不要だが、曖昧な型 assertion も作らない。

### M5 最終 cut と JS/TS

- paired benchmark と全 M5 runtime gate が完了するまで旧層へ変更を混ぜない。その後、inventory の
  delete/move/keep の三分類を一つの最終作業単位として適用する。
- `bindings/wasm` と `bindings/js` は全 source が旧 Go/WASM wire surface を所有するため削除する。
  `example/go` と `example/web/server` の旧 wiring、`example/web/client` の旧 protocol/graph/runtime
  application source と build manifest も削除する。この時点で動作する demo web は残さない。
- `example/assets` 等の codec/runtime contract に依存しない data、画像、license は独立 asset として
  残せる。Go/WASM import が無いという理由だけで旧 semantic DTO/graph compiler を残したり、逆に
  単独で意味を持つ asset を機械的に削除したりしない。
- `plugin/pcm/internal` は package 本体の linear PCM encoder/decoder を `_legacy/` の鏡像 path へ移し、
  独立した `adpcm` と `g711` subpackage は現在地に残す。旧 root test/wiring は削除し、残す二 package が
  旧 contract import なしで単独 compile することを検査する。

## 作業単位

### M5-1: ownership、allocator、queue、task foundation

1. `schema.Queue/Fanout` を削除し、typed shape binding と static contract validation を追加する。
2. bounded typed ring、limit trait validation、cancel/close/drain、fan-out move/fork を実装する。
3. Job/local buffer allocator、Overwrite lease、tracked task group、event model を実装する。
4. ownership/queue/allocator/task の unit/property/race/zero-allocation test を通す。

### M5-2: Program specialization と execution island

1. graph を dense runtime node、maximal linear island、必要な queue boundary へ compile する。
2. typed source -> queue -> fused Processor island -> queue -> sink と fan-out を実行する。
3. fan-in declaration、deterministic zip、Plan の island/buffer/watermark projection を実装する。
4. cancel、EOF/Flush、panic、observation off/basic の runtime test と leak test を通す。

### M5-3: Prepare/Run と transactional lifecycle

1. Host resource reservation、prepared Job、OpenContext narrow services、boundary binding を接続する。
2. reverse Open rollback、Finalize/Flush/Sync、multi-output prepare/commit/abort coordinator を実装する。
3. structured Result/error/outcome、bounded cleanup、idempotent Close を実装する。
4. partial Open、Finalize/Commit/Abort/Close failure、cancel、unjoined task を failure injection で検査する。

### M5-4: walking skeleton と performance gate

1. M4 PCM walking skeleton を public Prepare/Run 経路へ移し、bytes、sample、item count、order、PTS、
   EOF/Flush/Finalize、cancel を検査する。test 独自の routing loop と `Program.Open` は削除する。
2. hot-path 12 条を構造 test、allocation test、representative benchmark へ対応付ける。
3. M0 の旧 pipeline と新 runtime を同一 process の AB/BA harness へ接続し、correctness と allocation、
   明白な architecture regression の有無を記録してから cut の gate を開く。

### M5-5: 旧 contract 層の切断

1. inventory の delete 対象を削除し、algorithm を `_legacy/` の鏡像 path へ移す。
2. root/nested module、workspace、tool、CI/docs manifest から消えた surface/package を外す。
3. findings の M5 cut 対象を完了へ更新し、checkpoint に意図した capability hiatus を記録する。
4. `_legacy/` を除く旧 import/型名/registration/global façade の残存を検索し、new stack だけで
   build/test/docs gate を通す。

## 検証

各単位は変更 package と直接経路の `go test -race` / `go vet` を先に通す。M5-4 と M5-5 は runtime
architecture と module graph を広く変えるため、次を milestone gate とする。

```bash
go test -race ./flow ./media/buffer ./internal/run ./internal/memory ./internal/task ./internal/observe ./host ./plugin/pcm/linear
go vet ./flow ./media/buffer ./internal/run ./internal/memory ./internal/task ./internal/observe ./host ./plugin/pcm/linear
go test ./internal/run -run '^$' -bench '^BenchmarkLinear$' -benchmem
go build ./...
go run ./tools/cmd/docs-check
go run ./tools/cmd/test-runner --simd
```

cut 後は `go list ./...` に `core`、削除対象 sdk、CLI/WASM/demo/plugin 旧 package、`_legacy` が現れない
こと、`gofmt -l` が tracked Go source について空であることも確認する。

旧/new runtime の `BenchmarkRuntimePaired` は cut 前に同一 process で実行済みであり、結果と command は
[performance.md](../performance.md#m5-runtime-performance-gate) に固定した。source は旧 contract の再導入を防ぐため
`_legacy/internal/run/performance_test.go` に隔離し、cut 後の通常 gate からは外す。
