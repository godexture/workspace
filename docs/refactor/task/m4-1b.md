# M4-1b: key declaration と composition conflict

M4 の第 2 単位。この文書は手順であり、設計の正本は
[media.md](../media.md#key-identity-の重複を検出する)、
[architecture.md](../architecture.md#foundation-内部の依存方向)、
[planner.md](../planner.md#m4-1b-の条件) とする。

## 目的

同じ marker から異なる payload 型の key を宣言した構成を
`host.New` で拒否する。検出は既存の `plugin.Declaration` と
`internal/catalog` に載せ、key 専用 registry は作らない。

この単位では planner、`Compile`、`Plan`、`Program`、runtime を作らない。
walking skeleton の data path と descriptor path も変更しない。

## 手順

### 1. declaration target を一般化する

- `plugin.Declaration` の target を、catalog に実在すべき component identity と、
  payload を識別する `reflect.Type` の二種類として明示する。
- component target だけを catalog の component index と照合する。type target は
  valid な Go type であることだけを検証する。
- conflict は target kind と target value を含む列全体で比較する。同じ key と同じ
  target の重複は無害、同じ key と異なる target は error とする。
- declaration の canonical sort と catalog fingerprint が registration order に
  依存しないことを維持する。型の表示は package alias や pointer addressに依存させない。
- codec Binding、metadata Binding、Provider scheme の意味と target 実在検査を変えない。

### 2. key declaration constructor を `plugin` に置く

- `key.Key[T]` と `property.Key[T]` の双方を受ける一つの constructor を
  `plugin` に置く。両型が公開している `key.Erased` を利用し、容器別の constructor
  を作らない。
- declaration key は `key.ID` の共通 namespace を使う。property、metadata、side
  を別 namespace に分けない。
- payload target は marker identity ではなく key が宣言した Go payload type とする。
  `string`、`[]byte` 等を偽の marker identity へ変換しない。
- invalid key の問題を失わず、`host.New` の aggregate diagnostic へ流す。
- `media/key` は `plugin` を import しない。M4-1 の layering test を維持する。

### 3. 共通 vocabulary の declaration を公開する

- `media/tag` が現在定義する全 key の declaration を一つの関数から返す。
- 戻り値は呼び出し側が変更しても後続呼び出しへ影響しない。
- `standard` composition への組み込みは M6 に残す。

### 4. conflict を end-to-end で検査する

- 同じ marker と同じ payload 型を `key.Key[T]` と `property.Key[T]` から宣言しても
  `host.New` が成功する。
- 同じ marker を異なる payload 型で、同じ容器内および容器をまたいで宣言すると
  `host.New` が `catalog.declaration-conflict` を返す。
- key を declaration に加えなくても `property.Set`、`metadata.Document`、`side.Data`
  が従来どおり動く。
- codec Binding、metadata Binding、Provider scheme の conflict と missing component
  target の既存 test が引き続き通る。
