# M4-1c: foundation Example と設計文書の正本化

M4 の第 3 単位。この文書は手順であり、規則の正本は
[experience.md](../experience.md#三者の体験)、完了条件は
[planner.md](../planner.md#m4-1c-の条件) とする。

## 目的

実装済み foundation API の動く使用例を package の `Example` test に置き、
設計文書へ複製した未検査の Go code を正本にしない。M4-1b までに確定した
API を利用者・plugin 開発者の視点から通し、説明しづらい API があれば test
または Example の不足として直す。

この単位では production code の意味、planner、runtime、旧 plugin/surface を
変更しない。Example のためだけの convenience API も追加しない。

## 手順

### 1. public foundation package の Example を揃える

対象は `diagnostic`、`config`、`plugin`、`host`、`flow`、`access`、`endpoint` と、
M4-1b までに実装済みの全 `media/*` package とする。root `media` は production
package を持たない横断 harness なので、そこへ Example を作らず coverage test を置く。

- 既存 Example は保持し、package の中心 contract を既に示せているか確認する。
- Example がない package には、最小の正常系を一つ以上追加する。
- 複数 package を連携させる例でも、所有する概念の package に置く。似た fixture
  や helper を各 file へ複製しない。
- 表示結果に意味がある例は `Output:` で実行検査する。identity の package path
  など環境で変わる値は、安定した意味へ整形してから出力する。
- Example は公開 API だけを使い、旧 `core`/`sdk`、global registry、test 専用の
  内部実装へ依存しない。

### 2. 実装済み API の文書 code block を参照へ移す

`docs/refactor/*.md` の Go code block を一つずつ分類する。

- M4-1b までに実装済みの foundation API を説明する block は、対応する
  `example_test.go` への Markdown link と短い説明へ置き換える。
- M4-2 以降の `Job`、`Compile`、`Plan`、runtime、surface、未移植 plugin など、
  未実装 contract の概念例は残す。
- 古い API 名を示す block は、現行 Example へ置き換えるか、歴史的な反例として
  必要なら code fence を外して明示する。
- task 文書に記録された過去の patch/example は履歴なので、この正本化の対象外とする。

### 3. 文書と test の対応を検査する

- 各対象 package に少なくとも一つ `func Example` があることを repository test で
  機械的に固定する。新 package 追加時の規則は、その package を実装する milestone
  の review が担う。
- 文書から参照した Example が `go test` で実行される命名になっていることを確認する。
- `go doc` で Example が対象 package または symbol に関連付けられない名前を残さない。

## 検証

```bash
go test ./diagnostic/ ./config/ ./plugin/ ./host/ ./flow/ ./access/ ./endpoint/ ./media/... -race
go vet ./diagnostic/ ./config/ ./plugin/ ./host/ ./flow/ ./access/ ./endpoint/ ./media/...
go build ./...
gofmt -l .
go run ./tools/cmd/docs-check
```

単位完了時に [planner.md](../planner.md#m4-1c-の条件) を逐条確認し、
[checkpoint.md](../checkpoint.md) の M4 checkpoint を M4-2 へ進める。
