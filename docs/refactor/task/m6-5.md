# M6-5: file convenience と最小 CLI surface

M6 の利用 surface 単位。この文書は実装手順であり、Format と media 経路は
[media.md](../media.md#m6-完了条件)、利用者 surface は
[surfaces.md](../surfaces.md)、体験 gate は
[experience.md](../experience.md#m6-完了条件)、contract 分類は
[scope.md](../scope.md#m6-の-contract-分類) を正本とする。

> 状態: **進行中**

## 目的

M6-4 までで公式 composition と実 file/WAVE/PCM 経路は成立したが、利用者はまだ
`access.Reference`、Format component identity、graph、Host を自分で組み立てなければ変換できない。
さらに `job.Output` は Format を指定できず、拡張子が `.wav` でも raw writer が選ばれ得る。
入力側は content evidence の無い byte 列を既定 raw PCM として扱うため、rate/layout/endian を
捏造して雑音を正常出力する危険がある。runtime event は `Run` 完了後の `Result.Events` にしか現れず、
CLI は実行中の progress を表示できない。

M6-5a は Job に入力 Format hint と出力 Format request を追加し、Format 自身が宣言する拡張子を
catalog から解決する。raw fallback は意味を決める config を利用者が明示した場合だけ許す。
`plugin/file` の path constructor と `standard.Convert`/Job constructor を同じ Host 経路へ接続する。

M6-5b は observation を Host-global option から Run 単位へ移し、bounded live delivery と loss report を
追加する。その consumer として `cli.Run(ctx, h, args)` と `cmd/godec` を実装し、Plan preview、progress、
cancel、exit code を新 Host の上で動かす。

## 決定

### Format selector は Job boundary の immutable request である

- `job.Input` は任意の Format hint、`job.Output` は任意の Format request を持つ。explicit graph で
  boundary 直後・直前の Format component を pin した場合は省略できるが、selector と pinned component が
  両方ある場合は同じ Format でなければ diagnostic にする。無言で片方を優先しない。
- selector は Format identity による明示指定、または canonical extension hint/request の排他的な choice
  とする。入力と出力の choice、Format selector、config patch は defensive copy され、constructor 後の
  mutation で Job の意味が変わらない。
- 入力の extension は content evidence ではない。Probe の content match または malformed を先に評価し、
  content match があれば extension/identity hint より優先する。signature 一致後の malformed は別 Format や
  raw fallback へ降格しない。
- content match が無い場合、fallback は明示 hint が解決した Format と一致する候補だけを残す。hint が無い
  入力では fallback を全て除外し、`prepare.probe-mismatch` として失敗する。同順位 fallback を identity 順で
  選ばない。
- 出力 request が無く extension も無い場合は、Prepare が content/hint から選んだ入力 Format を優先する。
  extension が存在するが catalog に一致が無い場合は「request 無し」とみなさず、extension と利用可能候補を
  含む diagnostic にする。
- selector の表記そのものではなく、解決した Format/component/config が Plan execution identity に入る。
  同じ Format へ解決する `.wav` と `.WAV` が別 execution にならない。

### extension は Format identity の宣言であり catalog が索引する

- `media/format.Format` に canonical extension 宣言を追加し、Read/Write trait が同じ Format value を運ぶ。
  extension は lower-case、先頭 dot なしへ正規化し、空値、path separator、重複を composition diagnostic
  にする。宣言順ではなく canonical sort が trait manifest と catalog fingerprint に入る。
- WAVE は `wav`/`wave`、linear raw PCM は `raw`/`pcm` を宣言する。read-only/write-only Format も同じ
  identity 宣言を使えるが、入力解決は Read trait、出力解決は Write trait が存在する component だけを
  候補にする。
- 同じ Format identity を運ぶ複数 component の Format 宣言が一致しない場合は Host 構築時の composition
  diagnostic にする。同じ extension を異なる Format identity が宣言すること自体は許し、実際に selector
  として使われた時点で候補 identities を含む ambiguity diagnostic にする。
- 同じ Format identity・方向に複数 component 実装がある場合も、M8 の variant ranking を先取りせず
  ambiguity diagnostic にする。explicit graph で component を pin する escape hatch は既存どおり残る。
- `standard`、CLI、Host に公式 extension の固定表や identity type switch を置かない。第三者 Format は
  `standard.Set().Add(acme.Plugin())` と trait の extension 宣言だけで同じ path convenience に参加する。

### raw fallback は hint と意味 config の両方を要求する

- `.raw`/`.pcm` という locator extension だけでは、rate、valid bits、channel layout、endianness の既定値を
  承認したことにしない。extension hint は raw fallback 候補を指せても、必要な config が無ければ
  `prepare.format-config-required` で失敗する。
- content evidence を持たない Read trait は、fallback 時に明示を必要とする config field IDs を宣言できる。
  この情報は binding を Open 前に決めるための trait data であり、新しい registry や runtime service に
  しない。field ID が component schema に存在しない宣言は catalog composition diagnostic にする。
- linear raw reader は `rate`、`validBits`、`layout`、`endian` を要求する。`chunkSamples` は実行上の block
  tuning で media 意味を変えないため既定を許す。required field は config patch に明示的に存在する必要が
  あり、値が既定値と同じでも明示として扱う。preset 名だけで field の指定を推測しない。
- typed Job API と CLI は同じ sparse config patch を使う。Host や `standard.Convert` が extension から
  PCM properties を推測したり、CLI だけの raw default を持ったりしない。
- fallback の Plan node は従来どおり `Automatic` + `format.fallback` とし、content evidence が無いことと
  利用者 hint/config による選択であることを warning に残す。

### output Format は terminal constraint として solver に渡す

- Host は Prepare 中に output selector を catalog から一つの Write trait/component へ解決する。ただし
  component config が未指定なら default config で requested node を先に固定しない。linear writer の
  `Suggest` が inspected input の properties を引き継げなくなるためである。
- 選択 component は output boundary gap の **terminal candidate constraint** として solver に渡す。
  constraint は最終的に sink schema を作る候補だけを絞り、converter/resampler/codec/parser 等の非 terminal
  bridge は従来どおり候補に残す。Format 選択を solver の自由な gap-fill に戻さない。
- output request に component config が明示された場合、terminal component はその patch を固定して使う。
  config が無い extension request では通常の default + bounded `Suggest` を許し、linear raw output は入力
  sample properties を保つ。明示 patch と Suggest を暗黙 mergeして利用者指定を上書きしない。
- sink capability と spool adaptation は選択した Write trait の requirements から Compile/Solve 前に決める。
  output session の acquire は従来どおり Solve、resource reservation の後だけであり、`Host.Plan` は output
  objectを作成しない。
- solver が挿入した terminal Format node/edges は `Automatic` + `format.output` として Plan に現す。
  requested Format、選択 component、config、元 capability、spool 後 capability の説明可能性を維持する。

### file path convenience は file Provider と standard composition を再利用する

- `plugin/file` に platform path から canonical `file:` Reference を作る constructor を置く。relative path、
  absolute path、空白、Unicode、Windows drive/UNC、separator、URL escaping を roundtrip test し、利用者へ
  URL 構文を要求しない。Reference から path へ戻す既存 private 処理と同じ canonicalization owner に置く。
- `standard` に file-to-file Job constructor を置き、input/output path、必要なら input Format/config option を
  `job.Job` へ正規化する。constructor は catalog を持たず、path extension selector を Job に載せるだけとし、
  Format 解決は実際に使う Host catalog が行う。
- `standard.Convert(ctx, input, output)` は `standard.NewHost()`、同じ Job constructor、`Host.Run` だけを使う。
  別 planner、別 extension table、process-global registry、hidden graph executor を持たない。
- 一行 convenience は content-detectable WAVE input から WAVE/raw output を扱う。raw input は明示 config が
  必要なので一行 convenience では失敗し、typed Job API と CLI の具体的な設定方法を diagnostic に示す。
- custom Set の利用者は同じ Job constructor を捨てず、作った Job を
  `host.New(host.Plugins(standard.Set().Add(acme.Plugin())))` へ渡せる。第三者 extension の end-to-end を
  integration で検査する。

### observation は Run 単位に一本化する

- `host.Observe(mode)` を Host construction option から削除し、Host の observation field も削除する。
  immutable catalog/platform を共有する Host と、CLI/library/WASM ごと・実行ごとに異なる観測要求を
  同じ lifetime にしない。互換 wrapper や Host default と Run override の二重設定は残さない。
- `Prepared.Run` と `Host.Run` は同じ immutable Run option を受ける。observation off を既定とし、snapshot
  だけを保持する場合と live sink へ配送する場合を同じ event hub の option で表す。
- event history と live delivery はそれぞれ明示上限を持つ。live queue への enqueue は non-blocking とし、
  満杯時は media path を待たせず event を drop する。history overflow と delivery overflow の件数は
  `Result` の immutable observation summary に分けて残し、sequence gap と合わせて loss を隠さない。
- live sink は Host-owned dispatcher から immutable `host.Event` を順序どおり受ける。surface は queue、
  goroutine、runtime polling、media byte からの独自 progress 計算を実装しない。dispatcher は Run lifecycle
  に属し、success、failure、cancel、panic の全経路で close/join される。
- renderer/sink が error を返した場合はその error を cause として Job を cancel し、専用 observation phase
  の primary/cleanup diagnostic へ接続する。panic、停止しない renderer、Run 終了時の drain は既存の
  bounded cleanup 規則に従う。
- observation off は collector、counter、clock read、delivery queue、dispatcher goroutine を一つも作らない。
  Basic/Detailed/Trace の意味と schema Size/Time の評価条件は M5 の performance contract を維持する。

### CLI は Host の client に限定する

- `cli.Run(ctx, h, args)` を公開し、`Host` を注入する。CLI package は `standard.Set`、plugin factory、catalog
  registry、solver、queue、transaction 実装を持たない。`cmd/godec` だけが `standard.NewHost()` を呼ぶ。
- M6 の引数は input/output path、Plan-only preview、raw input Format/config に限定する。raw config は
  `job`/`config.Patch` と同じ field ID/codec で decode し、CLI 固有の PCM default や別 validation を作らない。
- preview-only は `Host.Plan` を使い output session/object を作らない。実行時は `Host.Prepare` で得た同じ
  Prepared の Plan を表示してから Run し、preview のために input session を閉じて再 acquire しない。
- progress は per-Run live event sink を terminal renderer へ接続する。drop count、Plan warning、structured
  diagnostic、output outcome を表示し、renderer error は Run cancellation になる。
- `cmd/godec` は signal-aware context を作り `cli.Run` の exit code を返す。success、usage、planning、runtime、
  cancellation を安定した code に分類し、error string の substring で分類しない。

## 非目標

- stdin/stdout と direct resource の Inspect 統合、Endpoint/device、playback、WASM/web、全 CLI flag は M9。
- MP4/multi-stream/mapping/stream copy/loss report は M7、MP3/FLAC/filter と variant selection は M8。
- MIME、HTTP header、remote object metadata を hint にすること、remote Provider retry/Snapshot は実 consumer の
  milestone に残す。M6 は file extension と explicit Format identityだけを扱う。
- raw properties の推測、signal analysis、extension を content evidence として扱うこと、malformed signature
  から raw への降格は行わない。
- surface が独自 scheduler、event queue、progress byte counter、transaction を持つ実装は作らない。

## 手順

### M6-5a-1. Format extension と fallback config contract を追加する

- `media/format` に canonical extension 宣言と fallback required config fields を追加し、clone、validation、
  trait manifest、catalog fingerprint、composition diagnostic を更新する。
- WAVE/linear/第三者 fixture に extension を宣言し、同 extension の別 Format、同 Format の別実装、read/write
  direction、invalid extension/field を検査する。

**途中 gate:** Host catalog が公式・第三者 Format の extension を方向別に解決でき、conflict を登録順に
依存せず診断する。`standard` と Host に公式 identity/extension の switch が無い。

### M6-5a-2. Job selector と file Reference/Job constructor を追加する

- `job.Input`/`Output` に immutable selector/config state と typed constructor/accessor を追加する。
- `plugin/file` の path constructor と `standard` の file Job constructor を追加し、extension は selector として
  Job に保持する。explicit graph との一致、unknown extension、extensionless output を検査する。

**途中 gate:** URL 構文を使わず file Job を構築でき、同じ Job が standard Host と第三者 definition を Add した
Host の双方へ渡せる。Job 構築時に catalog や filesystem I/O は発生しない。

### M6-5a-3. input hint と opt-in fallback を Prepare へ接続する

- Probe scheduler に selector/config を渡し、content-first、malformed terminal、hint-filtered fallback、
  extension ambiguity、required config field diagnostic を実装する。
- selected input Format nodeへ明示 patch を渡し、reason/warning/config provenance と replay lifecycle を維持する。

**途中 gate:** hint 無し arbitrary bytes と `.raw` path だけの入力は失敗し、明示 raw config では random/
sequential の両 sourceが同じ session/replay 経路で通る。WAVE bytes は誤った extension hint より content evidence
が優先される。

### M6-5a-4. output request を terminal constraint と capability binding へ接続する

- output selector を一つの Write component へ解決し、sink requirements/spool と solver terminal constraint を
  同じ選択から作る。terminal candidate 以外の bridge を除外しない。
- config 無しでは Suggest、明示 config では固定 patch を使い、inserted node/edge を `format.output` として
  Plan に投影する。

**途中 gate:** 同じ WAVE input を `.wav` と `.raw` へ出した Plan がそれぞれ WAVE mux/raw writer を選び、
sample properties を捏造しない。別 tag の codec candidate は除外されても Binding を持たない bridge は残る。

### M6-5a-5. standard convenience と第三者 extension E2E を通す

- `standard.Convert`、file Job constructor、Examples を追加し、WAVE→WAVE、WAVE→raw、same-path の明示拒否、failure時
  rollback、unknown/ambiguous extensionを検査する。
- integration の ACME Format を独自 extension で file convenience へ載せ、Set.Add 以外の登録が不要であることを
  検査する。

**M6-5a 完了 gate:** `standard.Convert(ctx, "in.wav", "out.wav")` 相当が一行で成功し、output extension
どおりの Format が Plan/byte output に現れる。raw input は hint/config無しで成功せず、第三者 Format は
trait declaration と `Set.Add` だけで同じ path convenience に参加する。

### M6-5b-1. per-Run bounded event hub を実装する

- Host-global Observe option/state を削除し、Prepared/Host Run option、bounded history、non-blocking live queue、
  dispatcher、drop summary、renderer failure cancellation を実装する。
- observation off performance、event ordering/clone、overflow、sink error/panic、cancel/close/join、Result snapshot を
  unit/race test する。

**途中 gate:** capacity 1 の遅い sink でも media Run は event enqueueで停止せず、drop count が Result に残る。
off では counter/clock/queue/goroutine が 0、sink failure は専用 phase と cause で Run を停止する。

### M6-5b-2. cli library と cmd/godec を追加する

- parser、Job normalization、Plan/event/result renderer、exit classification を `cli` に、standard composition と
  signal context を `cmd/godec` に置く。
- hermetic file E2E、preview-only、raw config、warning/diagnostic、progress/drop、cancel、renderer failure、exit
  code を検査する。

**途中 gate:** `cli.Run(ctx, h, args)` は injected Host だけで WAVE→WAVE/raw を実行し、preview は target を
作らない。command は cancel で rollback し、CLI package に plugin factory/solver/runtime queue が無い。

### M6-5b-3. 体験実測と M6 milestone gate を完了する

- `experience.md` に一行 library、CLI invocation、advanced Job への移行、raw explicit config、第三者 extension、
  progress/cancel の利用側 code と概念数を記録する。
- capability/checkpoint/task を更新し、M6 の全 completion condition と repository-wide gate を実行する。

## 検証

```bash
go test ./config/ ./job/ ./media/format/ ./internal/catalog/ ./internal/bind/ ./internal/bound/ ./internal/solve/ ./host/ ./plugin/file/ ./plugin/pcm/linear/ ./plugin/wave/ ./standard/ ./cli/ -race
go vet ./config/ ./job/ ./media/format/ ./internal/catalog/ ./internal/bind/ ./internal/bound/ ./internal/solve/ ./host/ ./plugin/file/ ./plugin/pcm/linear/ ./plugin/wave/ ./standard/ ./cli/
go test ./... -race                         # integration module 内
go vet ./...                                # integration module 内
go build ./...
go run ./tools/cmd/docs-check
go run ./tools/cmd/test-runner --simd
gofmt -l .
```

追加で次を検査する。

- extension と Format identity/component の解決が direction-aware、canonical、catalog order independent である。
- content evidence が input hint より優先され、malformed は terminal、fallback は hint/config opt-in である。
- output Format constraint が terminal component だけを絞り、converter 等の一般 bridge を残す。
- output config 無しの raw writer が inspected input properties を引き継ぎ、default PCM properties を捏造しない。
- Plan/Prepare/Run の success、failure、cancel 後に session、probe/replay handle、spool、temporary output、event
  dispatcher が残らない。
- live delivery overflow は media を block せず、history/delivery drop count、sequence、renderer failure が Result
  と terminal 表示で区別できる。
- Host-global observation state が残らず、複数の同一 Host Run が別 mode/sink を独立して使える。
- one-line standard API、advanced Job、CLI が同じ Host/Prepare/Run と同じ diagnostic/default を使う。
- official WAVE/PCM と第三者 ACME extension の file-to-file E2E が Fast/Realtime で green である。

**M6 完了 gate:** content evidence から選んだ WAVE input を一行 library API と公式 `godec` binary の双方で
WAVE/raw fileへ変換でき、Plan が input/output Format、理由、config、capability/spoolを説明する。raw input は
明示 hint/config無しに成功しない。実行中 event は bounded per-Run delivery から表示され、overflow/cancel/
renderer failureを隠さない。第三者 Format は core/standardを変更せず extension 宣言と Set.Add だけで同じ
file convenienceへ参加する。M6-0〜M6-4 の composition、conformance、failure、performance gate は green の
ままである。
