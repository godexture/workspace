# M4-4: 実 PCM と boundary binding

M4 の最終単位。この文書は実装手順であり、planner の完了条件は
[planner.md](../planner.md#m4-全体の条件)、Access/Endpoint の意味は
[access.md](../access.md)、audio representation は [audio.md](../audio.md) を正本とする。

## 目的

M4-3 までの planner を、互いに閉じた fixture ではなく実 linear PCM と Job boundary へ
接続する。raw PCM の property と typed sample schema、Access Provider/Endpoint の選択、
合成 filter region の converter 配置を同じ `Plan`/private `Program` 経路で検証し、M5 が
実行機構だけに集中できる状態で M4 を閉じる。

operator の scheduling、bounded queue、cancel/join、output transaction、Finalize 実行は M5
の担当である。M4-4 の binding は component を Open せず、静的 manifest、config、port、
capability を解決して Program に固定するところまでとする。

## 決定

### 実 PCM の配置と vocabulary

- 新実装は `plugin/pcm/linear` に置く。旧 `plugin/pcm/internal` は M5 の切断対象であり、
  そこへ新 contract を足して一時的に二実装を同じ package で compile しない。
- sample format、valid bit depth、sample rate、channel layout、wire endian は stream invariant
  であり frame field にしない。canonical property key と reusable planar sample schema は
  control-plane vocabulary package `media/sample` が所有し、data-plane の `media/audio` は
  `property` や `plugin` を import しない。
- linear PCM は raw framing、identity Parser、Decoder、Encoder を別 component にする。
  Parser は bytes を再解釈せず Chunk の ownership/timing を Packet へ移し、Decoder/Encoder
  だけが wire endian/packing と typed plane の間を変換する。
- 最初の実経路は signed 16-bit mono/stereo、little/big endian を扱う。unsupported depth、
  layout、端数 byte は compile/open 後の曖昧な failure ではなく、config/Compile または
  item validation の明確な diagnostic/error にする。

### Provider と Endpoint の binding

- `access.Provider` と `endpoint.Component` は、通常 component identity に結び付く immutable
  manifest のままとする。Host option で明示的に構成し、Host 構築時に target component の
  catalog 実在、scheme/endpoint 重複、role と port shape、静的 capability を検証する。
- Provider scheme conflict は既存 `plugin.Declaration`/catalog の一経路を使う。Host option が
  manifest の declaration を composition へ投影し、別の global registry や last-wins map を
  作らない。Host は検証後の manifest index だけを immutable に保持する。
- `internal/bind` が Job choice を graph boundary へ正規化する。reference は scheme から
  Provider component、endpoint request は component identity から trait を選び、config を
  Shape まで resolve してから requested graph の未接続 boundary へ結ぶ。
- M4 は一入力一出力の曖昧でない boundary を扱う。複数 stream/mapping/selector は実 MP4
  consumer のある M7 まで推測しない。直接 Resource の runtime adaptor と Provider acquire
  closure は M5 の `Prepare` が所有する。
- public Plan は Provider/Endpoint identity、direction、redacted reference、選択 capability、
  endpoint trait を inert projection として持つ。canonical reference、live resource、function、
  pointer を含めない。これらの binding state は Plan fingerprint に参加する。
- Format が宣言する `access.Requirements` は provider/source の利用可能 capability と純粋に
  照合し、選択した一つの alternative だけを narrow selection として Program に固定する。
  不足は component `Open` や type assertion より前の structured diagnostic にする。

### filter region gate

- S16 planar source と sink の間に、F32 planar だけを受け入れる identity filter を N = 1/4/16
  個並べる。converter は S16→F32 と F32→S16 の二種類だけを catalog に置く。
- 各 N で自動挿入 converter が最大二つ、filter region 内の全 descriptor schema が F32、
  boundary が S16 であることを Plan から検査する。速度ではなく graph structure を gate とする。

## 手順

### 1. boundary manifest と binder を実装する

- Provider の静的 capability と role、Endpoint trait を Host construction で索引し、既存
  declaration conflict と target validation を再利用する。
- graph 無しの一 input/一 output、および explicit graph の一意な open boundary を Job graph
  へ正規化する。unknown scheme/component、direction mismatch、ambiguous boundary、capability
  不足をそれぞれ stable code の diagnostic にする。
- binding projection を Plan canonical identity と private Program state へ追加し、reference
  secret/redaction、catalog order determinism、Open count zero を test する。

### 2. sample vocabulary と linear PCM を実装する

- `media/sample` に canonical property keys と S16P/F32P schema を置き、property clone/fingerprint
  と schema payload conflict を test する。
- `plugin/pcm/linear` に raw Format declaration、Chunk→Packet identity Parser、S16 Decoder/Encoder
  を実装する。component semantic は `Compile` に一度だけ書き、`Open` は private plan を消費する。
- known byte fixture を little/big endian、mono/stereo で decode/encode し、sample 値、plane、PTS、
  duration、round trip、ownership release を確認する。
- source→raw framing→Parser→Decoder→Encoder→sink を planner で解決し、auto insertion と Plan
  descriptor が実 PCM property を保持することを確認する。

### 3. converter placement を固定する

- synthetic filter chain test を `internal/solve` に追加し、N が増えても converter 数が二つを
  超えないこと、selected schema が region 単位で一定であることを検査する。
- M4 全条件を逐条監査し、対象 race/vet/build/docs gate を通して checkpoint を M4 完了へ進める。

## 検証

```bash
go test ./access/ ./endpoint/ ./host/ ./internal/bind/ ./internal/solve/ ./internal/program/ ./media/sample/ ./plugin/pcm/linear/ -race
go vet ./access/ ./endpoint/ ./host/ ./internal/bind/ ./internal/solve/ ./internal/program/ ./media/sample/ ./plugin/pcm/linear/
go build ./...
gofmt -l .
go run ./tools/cmd/docs-check
```

単位完了時は [planner.md](../planner.md#m4-全体の条件) を実装/test へ対応付け、Provider/
Endpoint binding、実 PCM、converter 数の三項だけでなく M4-1〜M4-3 の gate が引き続き成立する
ことを確認する。
