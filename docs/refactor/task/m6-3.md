# M6-3: shared Probe と自動 Format 選択

M6 の入力判別単位。この文書は実装手順であり、完了条件は
[media.md](../media.md#m6-完了条件) の Probe/Format 選択条項、Access lifecycle は
[access.md](../access.md#m6-完了条件)、contract 分類は
[scope.md](../scope.md#m6-の-contract-分類) を正本とする。

> 状態: **完了（2026-08-10）**

## 目的

M6-2c までの input binding は、Access boundary の直後に利用者が Format component を明示することを
前提に、その trait から capability を選んでから session を acquire する。自動判別では Format が
Probe の後にしか決まらないため、この順序のままでは probe session さえ取得できない。また M3 の
`ProbeView`/`RangeRequest` は宣言だけであり、候補間の cache、budget、反復、選択、prefix replay を
実行する consumer がまだ無い。

M6-3 は input binding を二段階化し、同じ acquired session と Host-owned bounded cache を使って
Format 候補を Probe する。content evidence を持つ WAVE を選択し、evidence が無い byte 列は raw PCM
の記録付き fallback として扱う。逐次読みしかない source では Probe が消費した prefix を同じ session
へ一度だけ replay する。選択した Format は solver の gap-fill ではなく Prepare が graph へ挿入し、
その後に Inspect、Shape/Compile、Solve を行う。

## 決定

### input binding は Format 選択の前後に分ける

- Bind の第一段階は Access Provider、reference、boundary node、宣言 capability までを確定する。
  adjacent component に Format read trait がある入力は従来どおり explicit input とし、その要求を
  直ちに選べる。read trait が無い入力だけを automatic Format slot として保留する。
- 保留状態は `internal/bound` の private state とし、`plan.Boundary.Valid` を緩めない。公開 Plan へ
  出す boundary は Probe 後の Format requirements と実 session capability から final selection を
  得たものだけにする。
- automatic input の probe acquire selection は `RandomRead` を第一候補、`SequentialRead` を第二候補
  とする。位置指定読みは cursor を動かさないため replay を作らない。どちらも無い source は Acquire
  前の capability diagnostic にする。
- probe 用に acquire した session を Inspect と Run でも使う。Probe 後に閉じて取り直さず、暗黙の
  reopen、cursor reset、候補ごとの acquire を行わない。Provider の acquire 回数は一 input、一
  Plan/Prepare につき一回である。
- Probe 後は選択 Format の `Requirements` を session の actual capabilities に対して評価し、最終
  `Opening` を作る。選択 Format が要求する capability を session が持たない場合は、Format identity、
  available capability、alternatives を含む Prepare diagnostic にする。
- output binding と spool selection は M6-2b の順序を維持する。Probe のために output session を
  acquire せず、`Host.Plan` は引き続き output を作成も truncate もしない。

### Probe は Read trait の bounded な control-plane 操作である

- `media/format.ReadTrait` に Probe を追加し、M6-0 の trait slot をそのまま使う。Probe 専用 registry、
  provider callback、operator、第二の extension map は作らない。
- Read trait の構築 API は requirements と任意の Probe/Inspect operation を一つの option 列で表せる
  形へ整理する。M6-2a の一時的な `ReadWithInspect` と Probe/Inspect の組合せごとの constructor を
  増殖させず、既存 consumer を新しい一つの形へ同時に移す。互換 wrapper は残さない。
- Probe は cancellation/deadline だけを通し `Value` を常に nil にする context と、Host が作った複数の
  immutable `access.ProbeView` だけを受け取る。session、Opening、reference、catalog、filesystem path、
  service locator は受け取らない。
- 一回の呼び出しは terminal result または一つ以上の追加 `RangeRequest` を返す。terminal result は
  content match、fallback、mismatch、malformed を区別する。I/O failure、cancel、panic は result に
  偽装せず既存の phase diagnostic channel へ送る。
- content match は選択理由を説明できる content evidence を一つ以上持つ。fallback は evidence を
  持たない低順位である。最高順位が複数なら registration/catalog order や identity 順で選ばず、候補
  identities と evidence を含む ambiguity diagnostic にする。同順位 fallback も同じ規則に従う。
- malformed は「その Format だと認識できた後に構造が壊れている」結果であり、fallback へ降格しない。
  単なる signature 不一致は mismatch とする。選択後の Inspect が malformed を返した場合も、別候補の
  Probe をやり直さない。
- Probe result、evidence、range 列は immutable copy を返し、同じ views に対する Probe は pure である。
  candidate 呼び出し順、result 集約、diagnostic detail は component identity で canonical にする。

### Host が range cache、budget、EOF を所有する

- Host は一 input の全候補で一つの range cache を共有する。同じ `RangeRequest` は一度だけ source から
  読み、同じ immutable view を各候補へ渡す。候補ごとの rewind、`Seek(0)`、再読を行わない。
- random session は要求 range を `ReadAt` で取得する。sequential-only session は現在 prefix の末尾まで
  しか読み進めず、要求 end が伸びる場合だけ単調に prefix を拡張する。offset まで読み飛ばした byte も
  replay と byte usage に含める。
- short read/EOF は cache の source end として記録し、候補が「まだ byte が来る」と誤認しない形で
  Probe context へ渡す。EOF 後の同一・包含 range 再要求は no-progress diagnostic にする。
- 空 range、overflow、同じ候補からの充足済み range の再要求、要求を返さない非 terminal result、
  source end を越える反復を fail closed にする。exact duplicate だけでなく既に cache が包含する range
  も再読しない。
- `job.Budget` に probe byte 上限と probe round 上限を追加する。byte usage は source から実際に取得・
  消費した unique byte、round usage は全 unresolved candidates を一度評価する scheduler round とする。
  一 candidate が一 byteずつ要求しても round limit で必ず停止する。
- default budget は WAVE の 12-byte signature と少数回の追加要求に十分な明示値を持つ。zero、overflow、
  非正値 round は invalid Job とする。exhaustion は unsupported/mismatch と分け、dimension、used、limit、
  最も近い unmet range/candidate を diagnostic に含める。
- `Budget.Duration` は Solve の内側だけで開始せず、Acquire、Probe、Inspect、Compile、Solve を含む planning
  pipeline 全体へ適用する。直接 `internal/solve.Resolve` を使う test/API の duration contract も維持する。
- `plan.Usage` に deterministic な probe bytes/rounds を載せ、`Budget` に対する validity と clone/
  fingerprint を更新する。wall-clock duration は従来どおり Plan fingerprint に入れない。

### prefix replay memory は Host-owned planning grant から取る

- `inputPlan` が input probe store と、その backing `buffer.Allocator`/handles の唯一の owner になる。
  allocator の grant は `job.Budget` の probe byte 上限であり、cache へ保持した unique byte と逐次 source
  で読み進めた gap/prefix を一度だけ charge する。無制限の `append`、候補ごとの `[]byte` copy、
  process-global cache は使わない。
- source からは allocator の write lease へ直接読み、commit 後の read-only handle を cache view とする。
  Host 用 view を作るために同じ range を GC heap へ再 copy しない。公開 constructor が持つ defensive
  copy の契約は維持する。
- random probe の cache handles は Probe/Inspect の必要期間が終われば解放する。sequential-only source
  の prefix handles は copy せず replay session へ move し、prefix を読み切った時点、または
  Plan/Prepared の Close・失敗・cancel の時点で release する。
- replay grant は planning budget が認可する Host resource であり、component の in-flight payload
  `resource.Request.Memory` へ混ぜない。Plan は budget と actual probe usage を別々に示し、runtime payload
  grant と二重計上しない。allocator の retained bytes が Close 後にゼロであることを検査する。
- `Host.Plan` は session と probe store を返却前に必ず閉じる。`Host.Prepare` は replay が残る場合だけ
  store を Run まで保持し、source operator が読む sequential view の前段へ replay decorator を置く。
  Provider component と Format component は replay の存在を知らない。

### Format 選択は Prepare が行い、solver へ annotation を渡す

- automatic input の候補は catalog 中の valid な Format read trait のうち Probe を持つ component とする。
  Probe を持たない explicit-only Format を候補へ入れず、空 Probe や identity type switch を fallback と
  して扱わない。
- WAVE Probe は最初に `[0, 12)` だけを要求し、`RIFF`/`RF64` と `WAVE` signature の一致を content
  evidence とする。signature を認識した後の truncation/malformed は WAVE failure のまま返す。
- raw PCM Probe は byte 内容を検出したと主張せず、range を要求しない低順位 fallback を返す。M6-3
  では既定 config で経路を通すが、その事実を warning に明記する。fallback を既定で許すか input hint
  opt-in にするか、rate/layout/endian/config をどの surface で渡すかは M6-5 の判断として残す。
- 選択 component は Access source と元の adjacent node の間へ deterministic ID で挿入する。default config
  を component schema で resolve し、Format component の output から元の graph までの gap は通常の
  solver が扱う。ただし Format 自体の選択を gap-fill としてやり直さない。
- Prepare が挿入した node/edges の annotation を internal transport で `ResolveBound` へ渡す。content match
  は `Automatic` + `format.probe`、fallback は `Automatic` + `format.fallback` として Plan に現す。
  fallback の Plan には Format/component identity、既定 config、content evidence が無いことを示す warning
  を一つだけ載せる。
- automatic graph rewrite の後に選択 Format を一度だけ Inspect し、その node-local Inspection と metadata
  resolver を CompileContext へ付ける。その後に Shape/Compile/Solve を行い、M6-2a の
  `Probe -> 選択 -> Inspect -> Compile -> Solve` 順序と Compile purity を維持する。
- non-seekable WAVE は signature match 後に WAVE requirements の capability diagnostic とする。Inspect を
  sequential 化したり input 全体を replay buffer へ入れたり、暗黙 spool/reopen へ落としたりしない。

## 非目標

- input format hint、MIME/extension hint、format-specific config の public surface、および evidence 無し
  fallback の product default は M6-5 で決める。
- Probe で media topology、sample properties、metadata を読むことはしない。それらは選択後の Inspect
  が担当する。
- Probe を solver candidate search、`Suggest`、component `Open` の一部にしない。
- non-seekable WAVE、remote Provider、input spool、Reopen を使う再取得、複数 input mapping は扱わない。
- arbitrary embedded artwork 等の control-plane allocation 上限は M8 の判断を維持する。

## 手順

### 1. Probe budget と Format trait contract を確定する

- `job.Budget`/`plan.Usage` に probe bytes/rounds を追加し、default、validation、clone、fingerprint、
  diagnostic を更新する。planning duration を Acquire から Solve まで一つの context で覆う。
- `media/format` に typed Probe context/result/evidence と Read trait option/accessor を追加する。
  `access.RangeRequest` は正の length と overflow-free end を要求する実 consumer のある contract にする。
- Host-created `ProbeView` が grant-backed read-only buffer を借用できる production constructor を追加し、
  public defensive-copy constructor と immutable read contract を維持する。

### 2. input binding と acquire を二段階化する

- `internal/bind` は explicit Format input と automatic Format slot を区別し、automatic input の incomplete
  selection を private bound state に保持する。
- random-first probe selection で session を一度だけ acquire し、actual capability を再検証する。
  explicit input、output/spool、direct boundary の既存 failure matrix を変えない。
- Probe 後に選択 Format requirements から boundary selection と Opening を finalize する helper を一箇所に
  集約し、Normalize と Host に capability selection の重複実装を作らない。

### 3. shared Probe scheduler と planning grant を実装する

- Host-private probe store を input plan に持たせ、budget-backed allocator、range cache、EOF、candidate state、
  byte/round usage を管理する。
- candidate identity 順の反復、range deduplication、random `ReadAt`、sequential prefix extension、cancel、
  no-progress、budget exhaustion、terminal selectionを実装する。
- match/fallback/mismatch/malformed と equal-rank ambiguity を構造化 diagnostic と Plan selection data へ
  変換する。

### 4. sequential prefix replay を実装する

- probe cache の prefix handles を同じ acquired session の `Sequential` view 前段へ move する decorator を
  Host 内部に置く。全 prefix を順番どおり一度だけ返してから元 session へ委譲する。
- short read、partial destination、cancel、EOF、Close、Probe/Run failure で byte の重複・欠落・handle leak
  が無いことを検査する。random-first source には decorator/store retention が無いことも固定する。

### 5. WAVE/raw Probe と自動 Format 挿入を接続する

- WAVE に 12-byte content Probe、linear raw reader に明示的 fallback Probe を付ける。
- Host が automatic boundary edge を選択 Format node を挟む graph へ書き換え、final capability selection、
  Inspect、Compile/Solve の順で進める。
- internal preselection annotation と warning/usage を Plan description へ渡し、automatic origin/reason、
  deterministic node ID/fingerprint を固定する。

### 6. end-to-end と failure matrix を通す

- Format node を含まない WAVE file inputを raw PCM output へ変換し、WAVE と parser が自動挿入されることを
  Fast/Realtime の両 preset で検査する。
- sequential-only source で raw fallback を選び、Probe prefix と残りの payload が byte-exact に一度だけ
  source operatorへ届くことを実行結果で検査する。
- explicit WAVE/raw、M6-2 metadata roundtrip、spool output、Host.Plan、Prepare/Run/Close の既存 gate を
  維持する。

## 検証

```bash
go test ./access/ ./job/ ./media/format/ ./plan/ ./internal/bind/ ./internal/bound/ ./internal/graph/ ./internal/solve/ ./host/ ./plugin/file/ ./plugin/pcm/linear/ ./plugin/wave/ -race
go vet ./access/ ./job/ ./media/format/ ./plan/ ./internal/bind/ ./internal/bound/ ./internal/graph/ ./internal/solve/ ./host/ ./plugin/file/ ./plugin/pcm/linear/ ./plugin/wave/
go build ./...
gofmt -l .
go run ./tools/cmd/docs-check
```

追加で次を検査する。

- random capability が sequential より優先され、Probe が source cursor を変えず replay allocation がゼロ。
- sequential-only source は一度だけ acquire され、全候補で同じ prefix read/cache を共有し、Run が同じ
  session から prefix と残りを byte-exact に読む。
- 同一・包含 range は再読されず、候補数を 1/10/100 と増やしても source read bytes は増えない。
- byte/round/duration exhaustion は mismatch/unsupported と異なる code で、candidate、unmet range、used、
  limit を報告する。cancel は Acquire/Probe/Inspect/Compile/Solve のどこでも同じ planning context から届く。
- WAVE signature match は `Automatic` + `format.probe`、raw fallback は `Automatic` + `format.fallback` と
  warning で Plan に現れる。equal-rank candidates は catalog order に依存せず ambiguity になる。
- WAVE signature match 後の malformed input と sequential-only WAVE capability failure は raw fallback に
  降格しない。
- Probe/Inspect は各 node で必要回数だけ実行され、Compile の複数回評価で再実行されない。同じ input
  snapshot、Catalog、Job、platform から同じ Plan fingerprint を得る。
- Plan/Prepared の success、failure、cancel、Close 後に probe allocator、replay handles、session、direct
  resource が残らず、`Host.Plan` は output session を acquire しない。

**単位完了 gate:** Format node を明示しない実 WAVE file が content evidence で選択され、raw PCM へ
変換できる。evidence の無い sequential input は記録付き raw fallback として同じ session の prefix を
一度だけ replay し、Plan が自動選択の理由と warning を説明する。M6-2 の walking skeleton と Host failure
matrix は green のままである。hint/config surface と fallback の product default は M6-5 へ残す。
