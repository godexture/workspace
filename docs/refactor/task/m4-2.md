# M4-2: explicit graph compile と validation

M4 の第 4 単位。この文書は手順であり、contract の正本は
[planner.md](../planner.md#compile-contract)、[runtime.md](../runtime.md#planner-pipeline)、
[surfaces.md](../surfaces.md#job-model) とする。

## 目的

pinned/explicit requested graph を、component instance を起動せずに Shape → Compile →
Validate へ通す。walking skeleton が手書きした descriptor 変換を component の純粋な
`Compile` へ移し、M4-3 の solver が同じ経路を候補評価に使える状態にする。

この単位では bridge 探索、rank、budget、public `Plan`、private `Program`、実 Access
session、runtime queue、Finalize 実行を作らない。

## 決定

### package 境界

- `job` は application が要求した input/output の tagged choice、pinned node/edge、
  exact stream mapping を所有する。selector language は実 consumer の MP4 が現れる
  M7 まで凍結しない。
- `resource` は第三者 component が返す request/estimate と Host が後に返す grant の
  単位を所有する。allocator、pool、accounting は M5 の `internal` に置く。
- component contract は [C21](../decisions.md#c21-foundation-package-は-media-領域だけを-grouping-する)
  のとおり `plugin.Component` に置き、`component` package を新設しない。
- graph の mutable build state、topological order、validation は `internal/graph` に置く。
  public graph executor/registry は作らない。

### component Spec

- config 型 `C`、private compiled plan 型 `P`、control-plane descriptor 型 `D` を知る
  `plugin.Spec[C, P, D]` を、generic
  `plugin.WithSpec` が一度 type erase して `Component` に保持する。
- `Shape(C)`、`Compile(CompileContext, C, flow.Descriptors[D])`、
  `Open(OpenContext, P)`、optional `Suggest` を一つの Spec に集約する。
- static shape も `Shape` の特殊例とし、static/dynamic で component family を分けない。
- `Compile` の返り値は output descriptors、structured requirements/effects、resource
  request/estimate、private plan を同時に持つ。`Open` はその private plan だけを受け、
  descriptor 変換を再計算しない。
- `Compilation` は component implementation と結び付け、別 component や別 Spec の
  compilation を `Open` に渡すと失敗させる。private plan の `any` を surface へ出さない。
- `Suggest` は typed config 候補だけを返す。Component 境界で schema resolve、canonical
  fingerprint の duplicate、宣言上限を検証する。候補 output は必ず `Compile` が求める。

### descriptor と graph

- `flow.Descriptors[D]` は port ID と descriptor の ordered binding。media graph では
  `D = stream.Descriptor` とする。`flow`/`plugin` から `media/stream` を import して cycle を
  作らず、third-party control-plane descriptor も閉じない。many port の
  複数 binding を保持し、map iteration を canonical order に使わない。
- requested node は caller が付ける `job.NodeID`、component marker identity、immutable
  config patch を持つ。edge は node/port endpoint を二つ持つ。
- `internal/graph.Compile` は config resolve、dynamic Shape、topological Compile、全体
  validation の順で進む。component `Open` は呼ばない。
- source は input port が 0、sink は output port が 0 の node とする。M4 では cycle を
  許す宣言が存在しないため全 cycle を拒否する。
- finalization は実行しない。Compile が finalization を要求した node に Spec の明示的な
  finalizer capability が無ければ plugin bug として compile 時に拒否する。実 lifecycle
  callback は M5 が接続する。
- 同じ schema marker を異なる Go payload 型へ結び付けた component は catalog で拒否し、
  dynamic Shape 間の接続も graph validation で再検査する。identity だけでは typed edge の
  factory 互換性を保証できず、factory pointer の比較では同じ宣言の再構築を誤拒否するため、
  identity と payload 型の組を wiring compatibility とする。
- Spec は全 component に必須とする。Open 後の operator shape は compile 済み Shape と一致
  しなければ operator を閉じて拒否する。

## 手順

### 1. `resource` と `job` の値 contract を作る

- byte/work/duration/confidence の typed unit、Request/Estimate/Grant を追加し、負値、
  無効 confidence、request を満たさない grant を検証する。
- Input/Output は reference、direct resource、endpoint request の kind を constructor で
  排他的に作る。zero/複数 kind を作れる public field は置かない。
- Graph/Node/Edge/Mapping は immutable copy を返し、空 ID、未知 node、duplicate node/
  edge/mapping を structured diagnostic にできる情報を保持する。

### 2. Shape/Compile/Suggest/Open を `plugin.Component` に統合する

- M3 の `WithPorts`/引数なし `WithOpen` を削除し、全利用側を `Spec` へ移す。互換 wrapper
  は残さない。
- Shape、Compile、Suggest の panic は component/phase 付き diagnostic error へ変換する。
- Compile result の output port、descriptor validity、requirement/effect/resource validity を
  boundary で検証する。
- Suggest は repeat call で同じ fingerprint 列になること、上限、duplicate absence、
  Open を呼ばないことを test する。
- dynamic mixer fixture で config の input count が Shape の many input port 列を決め、
  runtime の入力数から topology を推測しないことを確認する。

### 3. explicit graph を compile/validate する

次を個別の stable diagnostic code で拒否する。

- schema mismatch、invalid/unresolved time base
- required input/output 未接続
- one port の重複接続、many 宣言のない fan-in/fan-out
- unknown node/port、duplicate node/edge/mapping
- cycle、source から到達不能、sink へ到達不能
- Compile の unresolved Requirement
- finalization requirement と Spec capability の不一致

error は一件で停止せず、独立に判定できる問題を aggregate する。validation の結果順は
node ID、port ID、edge の canonical order に固定する。

### 4. walking skeleton を Compile 経路へ移す

- source → demuxer → parser → decoder → encoder → muxer と metadata branch の全 component
  に Spec を持たせる。
- descriptor 変換は test driver から各 component の Compile へ移す。
- `internal/graph.Compile` が返した compilation だけを Open に渡し、従来の direct
  `Component.Open()` を削除する。
- bytes、item 数、順序、timestamp、unknown property、raw metadata preservation の既存
  assertion を維持する。
