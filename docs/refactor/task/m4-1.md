## 手順

手順 1〜4 は各々独立に compile と test が通る状態で終える。5 は 1〜4 の完了後、6 は最後。

### 1. `media/key` を新設する

marker 由来 typed key の機構を一つにする。移行前の `media/property` の `Key[T]`/`Define`/`ID` と `media/metadata` の `Key[T]`/`DefineKey`/`KeyID` は、識別子名と error 文言以外が同一実装である。

- 置くもの: `key.ID`、`key.Key[T]`、`key.Define[Marker, T](clones ...func(T) T)`、`key.Erased`、`key.ErrType`。
- **依存は `internal/marker`、`internal/snapshot`、stdlib だけ。`plugin` を import しない。** この package は data plane の閉包に入る（手順 5 の test が固定する）。宣言の構築子をここに置かない。
- `key.Erased` は identity、payload の `reflect.Type`、宣言された clone を erased 形で運ぶ concrete 型。`media/key` の外から構築できないようにする。`key.Key[T]` と `property.Key[T]` の両方がこれを返し、M4-1b の宣言構築子と容器の格納経路が共有する。
- 問題は構築時 error ではなく `Problem()` に保持する（[C19](../decisions.md)）。

### 2. 三つの容器を `media/key` へ載せ替える

- `metadata.Document` と `side.Data` は `key.Key[T]` をそのまま使う。**一つの marker 宣言が両方で通ることを test で確認する。**
- `property.Key[T]` は同じ機構の上に **canonical encoder の宣言義務**を加えた別型にする。宣言がなければ `Valid()` を false にし `Problem()` に理由を持たせる。理由は [planner.md](../planner.md#descriptor-state) の fingerprint、規則の出所は [config.md](../config.md#immutability-と-canonicalization)。
  - 構築子は `property.Define` の名前を保つが、`key` の機構へ委譲する**新しい実装**にする。canonical encoder を要求するので signature が変わり、既存の呼び出し 2 箇所（`media/stream` の test）は書き換えになる。
  - 標準 scalar 型（bool、整数、有限 float、string、enum）の既製 encoder を用意する。第三者に定型 code を書かせない。
  - fingerprint の計算と `property.Set` の canonical 表現を組み立てる関数は M4-3。ここは**宣言できるところまで**。
- 構築子は二つで三つにならない。**容器は三つ、key 型は二つ**だからである。`metadata` と `side` は `key.Key[T]` をそのまま使うので自前の構築子を持たず、`metadata.DefineKey` の呼び出し側（`media/tag` の共通 vocabulary と各 test）は `key.Define` へ移す。
- 容器は統合しない。`property.Set`、`metadata.Document`、`side.Data` は独立した型のまま。scope、順序、origin、raw block は `Document` だけが持つ。
- 削除して呼び出し側を移す（alias も wrapper も残さない）。
  - identity 型 `property.ID` と `metadata.KeyID` → `key.ID` に一本化する。namespace を property と metadata/side で共有し、容器をまたいだ重複を M4-1b が検出できるようにするため。
  - `property.ErrPropertyType` と `metadata.ErrKeyType` → `key.ErrType`。
  - `metadata.Key`/`DefineKey`/`Erased` → `key.Key[T]`/`key.Define`/`key.Erased`。
  - `property.IdentityOf` と `metadata.KeyIdentityOf` → 移さずに消す。repository 全体で呼び出し元が 0 件である。
- 多重度は key に宣言させない（[media.md](../media.md#多重度の宣言は持たない)）。`Values`/`First` の形を変えない。

### 3. `media/carrier` を新設する

carrier identity を [media/format/format.go](../../../media/format/format.go) から移し、marker 由来にする。

- 置くもの: `carrier.ID` と marker からの宣言。依存は `internal/marker` と stdlib。
- **identity を marker 由来にする。** 現在の `CarrierID string` は第三者が一意性を保証する手書き文字列で、`metadata.Bind` がその値をそのまま declaration key に使う。[C8](../decisions.md) を例外なく成立させる。
- **`Owner` を削除する。** 読む側は `format.Define` の非空検査と test 1 件だけで意味の consumer がない。field が 1 つになるので `Carrier` struct 自体も消え、`format` は `[]carrier.ID` を持つ。
- `media/metadata` の `RawBlock`/`Origin`/`Bind`/`BindingKey` を `carrier.ID` へ移し、`media/format` を import しない状態にする。
- `format.Tag`（WAVE の `0x0055` 等）は identity ではなく規格由来の data なので変えない。

### 4. `media/format` の alias を削除する

`type Capability = access.Capability`、`Alternative`、`AnyOf`、`SequentialRead` 以下 6 個の const 再 export を削除する。利用側は `access` を直接 import する。同じ概念に import path を 2 つ持たせない。

### 5. 依存制約を test で固定する

`media/packet` と `media/audio` の推移的依存が `media/{buffer,timing,side,key}` と `internal/{marker,snapshot}` に閉じていることを検査する。

現状:

```text
media/packet -> media/side -> media/metadata -> media/format -> access -> plugin -> config, flow, diagnostic
```

手順 1〜3 の後: `media/packet -> media/side -> media/key`

- 置き場所は `media/layering_test.go`（`package media_test`）。
- `go/build` で import graph を再帰的に辿る。`os/exec` で `go list` を起動する形でもよいが、stdlib だけで完結する前者を優先する。
- この test は M4-1b が `plugin` に key 宣言の構築子を足す時の回帰検査も兼ねる。`media/key` が `plugin` を import し返していないことを一つの test が両単位で保証する。
- [quality.md](../quality.md#repository-wide-ci) の `structure` gate が M10 でこれを取り込む。

### 6. skeleton に `stream.Descriptor` を通す

`media/foundation_test.go` の skeleton は `stream.` と `property.` を一度も参照しておらず、`media/stream` は repository 全体で importer を持たない。M4-2 以降の `Compile` はこの descriptor を入出力に取り、M4-3 の fingerprint はその上に載る。solver を積む前に実際に流して確かめる。

- 各 component が入出力 port ごとに `stream.Descriptor`（schema identity、`timing.Base`、`property.Set`、`metadata.Document`）を持つ。
- 駆動 loop が item と descriptor を並走させる。demuxer が descriptor を生成し、parser/decoder/encoder/muxer が受け取った descriptor から次を導き、末端で検証する。
- sample rate 相当の property を `property.Define` で宣言し、末端まで運ぶ。**core がその property を解釈しないこと**と、component が宣言した property だけを読むことを確認する。
- `timing.Base` を stream ごとに持ち、time base が変わる箇所で checked rescale を通す。**rescale が現れない skeleton にしない。** M7 の MP4 が per-track timescale で本格的に使う経路の最初の consumer になる。
- descriptor 変換規則を component の contract として固定しない。それは `Compile` の責務で M4-2 が決める。この単位では test code が変換を書く。
- **skeleton の位置付けを変える。** M3 の成果物ではなく、以後の全 milestone が自分の contract を通す恒久的な回帰 harness とする。この意図を先頭 comment に書く。

## 既存の機構を使う

新しい仕組みを作る前に M2/M3 の口を使う。重複を作ったら差し戻す。

- identity 導出は `internal/marker`。`media/key` と `media/carrier` に独自の marker 解析を書かない。
- clone 規則は `internal/snapshot`。C17 の判定を書き写さない。
- 借用と共有は `media/buffer.View`/`Handle` と `flow.Input` が確立した形（accessor は借用を返し、共有は明示）。
