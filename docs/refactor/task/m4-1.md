## M4 全体の分割

分割の判定規則は **各単位が walking skeleton を端から端まで green のまま残すこと** である。正本は [planner.md](../planner.md#作業単位)。

## この単位の最優先規則

**新しい contract を作らない。**

M4-1 は M3 の成果に対する構造是正と、既存 skeleton の拡張だけを行う。`Compile`、`Suggest`、`Shape`、`job`、`resource`、`Plan`、`Program` はこの単位に存在しない。それらは M4-2 以降の担当であり、この単位で先取りすると受け入れ基準が曖昧になる。

key の重複検出も、`plugin.Declaration` の contract を広げる判断を含むためこの単位に置かない。M4-1b が担当する。

例外は `media/key` と `media/carrier` の 2 package だが、これらは新しい概念ではなく、既に 3 箇所へ複製されている機構と、既に `media/format` の中にある型を、正しい場所へ移すものである。

## スコープ

**やること**: foundation package の再編、`media/format` の alias 削除、依存制約の test 固定、walking skeleton の control plane 化。

**やらないこと**:

- `core`、`sdk`、`plugin/<family>`、`cli`、`bindings`、`example` の変更。旧経路はそのまま動かし続ける（切断は M5）。
- key の宣言・重複検出・`plugin.Declaration` の変更（M4-1b）。
- `Example` の整備と設計文書の code block 置換（M4-1c）。
- planner、solver、`Plan`、`Program`、scheduler、queue、execution island。
- `Compile`、`Suggest`、動的 `Shape`、variant、`resource`、`job`。
- 実 Format/Codec の実装、`standard`、`integration`、`testkit`。
- `access`/`endpoint` の contract 拡張。この単位では触らない（`media/format` が re-export をやめて `access` を直接使う形にするだけ）。

## 作業

### 1. `media/key`

marker 由来 typed key の機構を一つにする。設計の正本は [media.md](../media.md#key-機構は一つ容器は三つkey-型は二つ)。

現在 [media/property/property.go](../../../media/property/property.go) の `Key[T]`/`Define`/`ID` と [media/metadata/key.go](../../../media/metadata/key.go) の `Key[T]`/`DefineKey`/`KeyID` は、識別子名と error 文言以外が同一実装である。struct field、`marker.Canonical` → 可変長 clone 検査 → `snapshot.NeedsClone` → 既定 shallow copy という `Define` の分岐、`Valid`/`ID`/`ValueType`/`Problem`/`cloneAny`、非公開 method を持つ `keyLike` interface のすべてが重複している。`media/side` は 3 つ目の consumer として `metadata.Erased` 経由でこの機構に相乗りしている。

**機構は一つ、容器は三つ、key 型は二つにする。**

`media/key`:

- `key.ID`、`key.Key[T]`、`key.Define[Marker, T](clones ...func(T) T)`、`key.Erased`、`key.ErrType`。
- **依存は `internal/marker`、`internal/snapshot`、stdlib だけにする。`plugin` を import しない。** この package は data plane の閉包に属し、作業 4 の test が固定する。宣言の構築子をここへ置かない。
- `key.Erased` は identity、payload の `reflect.Type`、宣言された clone を erased 形で運ぶ concrete 型とする。`media/key` の外から構築できないようにし、`key.Key[T]` と `property.Key[T]` の両方が返せる形にする。M4-1b の宣言構築子と、容器の格納経路がこの view を共有する。
- `metadata.Document` と `side.Data` はこの `key.Key[T]` をそのまま使う。一つの marker 宣言が両方で通ることを test で確認する。`metadata.Erased` はこの共有によって不要になるので削除する。

`media/property`:

- `property.Key[T]` は `key` の機構の上に **canonical encoder の宣言義務**を加えた別型とする。canonical encoder を宣言しない `property.Key` は `Valid()` を false にし、`Problem()` に理由を持たせる。`host.New` が集約報告する既存の形（[C19](../decisions.md)）に従い、構築時に error を返さない。
- 理由は [planner.md](../planner.md#descriptor-state) の descriptor fingerprint である。property 値は canonical key/value として fingerprint に参加し、metadata entry と side data は参加しない。canonical 表現を持てない key を `property.Set` へ入れる経路を、実行時ではなく宣言時に閉じる。[config](../config.md#immutability-と-canonicalization) が config field に課している規則と同一で、適用条件も同じ「値が fingerprint に入るか」である。
- fingerprint の計算そのものは M4-3 の担当である。M4-1 は encoder を**宣言できる**ところまでとし、`property.Set` の canonical 表現を組み立てる関数は M4-3 が書く。宣言だけを先に置くのは、後から義務を追加すると全 property 宣言を書き直すことになるためである。
- 標準 scalar 型（bool、整数、有限 float、string、enum）には既製の encoder を用意し、第三者が定型 code を書かずに済むようにする。

削除:

- `property.ErrPropertyType` と `metadata.ErrKeyType` は `key.ErrType` に統合する。
- `property.Define`/`property.ID`、`metadata.Key`/`metadata.DefineKey`/`metadata.KeyID`/`metadata.KeyIdentityOf`/`metadata.Erased` を削除し、呼び出し側を移す。alias や wrapper を残さない。
- 容器は統合しない。`property.Set`、`metadata.Document`、`side.Data` はそれぞれ独立した型を維持する。scope、順序、origin、raw block は `Document` だけが持つ。

多重度（`Title` は単一値、`Artist` は複数値）は **key に宣言させない**。理由と担当は [media.md](../media.md#多重度の宣言は持たない) を参照する。この単位で `Values`/`First` の形を変えない。

### 2. `media/carrier`

carrier identity を [media/format/format.go](../../../media/format/format.go) から `media/carrier` へ移し、marker 由来にする。

[media.md](../media.md#carrier) は Carrier を Format/Codec と並ぶ独立概念として分離しており、format-owned だけでなく codec/bitstream-owned carrier も存在すると明記している。format の内部型のままだと、codec が所有する carrier が format 由来に見え、`media/metadata` が carrier identity 一つのために `media/format` を import することになる。

- `carrier.ID` と marker からの宣言を `media/carrier` に置く。依存は `internal/marker` と stdlib。
- **identity を marker 由来にする。** 現在の `CarrierID string` は第三者が一意性を保証しなければならない手書き文字列であり、`metadata.Bind` がその値をそのまま declaration key に使うため、二つの plugin が同じ `"id3"` を選んだだけで衝突する。[C8](../decisions.md) を foundation 全体で例外なく成立させる。
- **`Owner` を削除する。** 現在 `Carrier` は `Identity` と `Owner string` を持つが、`Owner` を読む側は `format.Define` の非空検査と 1 件の test だけで、意味の consumer がない。marker から導いた identity の package path が宣言元をそのまま示す。field が 1 つになるため `Carrier` struct 自体も不要になり、`format` は `[]carrier.ID` を保持する。format と codec のどちらが所有するかを型で区別する必要が生じるのは M8 であり、その実 consumer を前にして決める。
- `media/metadata` の `RawBlock`/`Origin`/`Bind`/`BindingKey` は `carrier.ID` を使い、`media/format` を import しない。
- 規格側の値である `format.Tag`（WAVE の `0x0055` 等）は identity ではなく data なので、marker 化の対象外である。現状の型を変えない。

### 3. `media/format` の alias 削除

`type Capability = access.Capability`、`Alternative`、`AnyOf`、および `SequentialRead` 以下 6 個の const 再 export を削除する。同じ概念に import path が 2 つ存在する状態をなくす。利用側は `access` を直接 import する。

### 4. 依存制約の固定

`media/packet` と `media/audio` の推移的依存が `media/{buffer,timing,side,key}` と `internal/{marker,snapshot}` に閉じていることを test で固定する。

現状はこの chain で control plane 全体へ到達している。

```text
media/packet -> media/side -> media/metadata -> media/format -> access -> plugin -> config, flow, diagnostic
```

作業 1 と 2 の後は `media/packet -> media/side -> media/key` になる。

test は `go/build` で import graph を再帰的に辿り、data plane package の閉包に control plane package が含まれないことを検査する。`os/exec` で `go list` を起動する形でもよいが、stdlib だけで完結する前者を優先する。置き場所は `media/layering_test.go`（`package media_test`）とし、既存の `media/foundation_test.go` と同じ位置に置く。[quality.md](../quality.md#repository-wide-ci) の `structure` gate が M10 でこれを取り込む。

この test は M4-1b が `plugin` に key 宣言の構築子を足す時の回帰検査でもある。`media/key` が `plugin` を import し返していないことを、この一つの test が両単位で保証する。

### 5. walking skeleton の control plane 化

`media/foundation_test.go` の skeleton に `stream.Descriptor` を通す。

現在 skeleton は `stream.` と `property.` を一度も参照しておらず、`media/stream` は repository 全体で importer を持たない。M4-2 以降の `Compile` は `stream.Descriptor` を入出力に取り、M4-3 の fingerprint はその canonical 表現の上に載る。solver を積む前に、descriptor が実際に組み立てられ、port 間を流れ、末端まで届くことを確認する。

- skeleton の各 component が入出力 port ごとに `stream.Descriptor` を持つ。descriptor は schema identity、`timing.Base`、`property.Set`、`metadata.Document` を持つ。
- 駆動 loop が item と descriptor を並走させる。demuxer が descriptor を生成し、parser/decoder/encoder/muxer が受け取った descriptor から次の descriptor を導き、末端で検証する。
- sample rate 相当の property を `property.Define` で宣言し、`property.Set` へ入れて末端まで運ぶ。core がその property を解釈しないこと、component が宣言した property だけを読むことを確認する。
- `timing.Base` を stream ごとに持ち、component 間で time base が変わる箇所で checked rescale を通す。rescale が現れない skeleton にしない。M7 の MP4 が per-track timescale で本格的に使う経路であり、ここが最初の consumer になる。
- descriptor 変換規則を component の contract として固定しない。それは `Compile` の責務であり M4-2 が決める。この単位では skeleton の test code が変換を書く。

**skeleton の位置付けを変える。** M3 の成果物ではなく、以後の全 milestone が自分の contract を通す恒久的な回帰 harness とする。この意図を skeleton の先頭 comment に書く。

## 既存の機構を再利用する

新しい仕組みを作る前に、M2/M3 が用意した口を使う。重複を作った場合は差し戻す。

- identity 導出: `internal/marker`。`media/key` と `media/carrier` に独自の marker 解析を書かない。
- clone 規則: `internal/snapshot`。C17 の判定を書き写さない。
- 問題の保持と集約: 構築時 error を返さず `Problem()` に保持し、`host.New` が集約する形（[C19](../decisions.md)）。`media/key` もこれに従う。
- 借用と共有: `media/buffer.View`/`Handle` と `flow.Input` が確立した「accessor は借用を返し、共有は明示」の形。
