# M6-2a: Inspect と WAVE 読み経路

M6-2 の読み側単位。この文書は実装手順であり、完了条件は
[media.md](../media.md#m6-完了条件) の WAVE/Inspect 条項、Access lifecycle は
[access.md](../access.md#m6-完了条件)、contract 分類は
[scope.md](../scope.md#m6-の-contract-分類) を正本とする。

> 状態: **未着手**

## 目的

M6-1 は実 file session を Prepare で acquire できるようにしたが、Shape/Compile/Solve が終わった
後に acquire している。WAVE の出力 descriptor は `fmt ` chunk を読まなければ確定できないため、
この順序では実 file から WAVE を compile できない。

M6-2a は Prepare を `Acquire -> Inspect -> Shape/Compile -> Solve` の順へ直し、明示指定された WAVE
Format が同じ input session を Inspect と実行で共有する経路を作る。単位終了時には、fixture が
carrier descriptor へ PCM properties を捏造せず、実 WAVE file の header だけから raw PCM file を
書き出せる状態にする。

## 決定

### Inspect と format 選択を分ける

- Inspect は「既に選ばれた Format の header を読む」操作であり、M6-2a が担当する。
- Probe は「どの Format かを決める」操作であり、M6-3 に残す。M6-2a の Job は WAVE component を
  明示する。
- **format 選択を solver の gap-fill にしない。** 自動判別を加える M6-3 も、documented pipeline
  どおり `Probe -> 選択 -> Inspect -> Shape -> Compile -> Solve` の順で処理する。solver が WAVE
  demux 候補を挿入した後に Inspect する設計は、この単位が確定する Compile contract と両立しない。
- M6-2a は probe、候補間の prefix 共有、非 seekable input の replay を実装しない。これらは
  M6-3 の実 consumer と一緒に決める。

### Inspect は Format trait の操作にする

- `format.ReadTrait` に、選択済み input opening を読む context-aware な Inspect 操作を加える。
  raw PCM のように config だけで descriptor を決められる Format は Inspect を持たなくてよい。
- Inspect は component の `Open` を呼ばない。Parse は Compile より前、Open は Program 確定後なので、
  Inspect を operator lifecycle に入れると循環する。
- Inspect が返す値は immutable な node-local snapshot とし、header から確定した output descriptor と
  実行時に必要な framing 情報を一つの結果として運ぶ。session、reader、catalog、credential を値へ
  閉じ込めない。
- Inspect は explicit node ごとに一度だけ実行する。solver の budget 内で同じ component の Compile が
  複数回呼ばれても再実行しない。Compile は同じ Inspect 結果に対して pure でなければならない。

### Inspect 結果の transport は既存 trait 機構を共有する

- `plugin.CompileContext` が node-local prepared value を marker key で保持できるようにする。ただし
  prepared value 専用の単一 slot や別の汎用 map を新設しない。
- M6-0 の `plugin.TraitKey`、marker key、型消去 slot、重複 key 検出を component と CompileContext で
  共有する。実装上は trait store の内部表現を共通化し、値の付き先だけを分ける。
- 低水準の型消去値を扱うのは `plugin` の bridge に限る。WAVE と Host は `media/format` が提供する
  型付き attachment/accessor を使い、`any` の assertion や format kind の type switch を持たない。
- 同じ context trait key を二度付ける経路は fail closed にする。順序依存の上書きを許さない。
- この transport は将来 probe 結果や spool 判断を運べる形を持つが、この単位で consumer の無い
  typed value や trait 種を宣言しない。

### Plan と Prepare の段階順を分けて定義する

共通の resolve を一枚の関数に押し込まず、side effect と所有期間が読める段階へ分ける。

`Host.Plan` は次の順で行う。

1. Job を normalize/bind し、input boundary と宣言 capability selection を確定する。
2. input session だけを acquire し、実 capability と selected narrow view を再検証する。
3. 明示 Format を Inspect し、node-local CompileContext を作る。
4. Shape/Compile/Solve/Validate/Optimize/Describe を行い、inert Plan を作る。
5. acquire した input session と Host-owned direct resource を、成功・失敗のどちらでも返却前に閉じる。
   borrowed direct resource は閉じない。

`Host.Plan` は resource reservation を保持せず、output session/transaction を acquire せず、target の
作成・truncate・commit を行わない。

`Host.Prepare` は 1〜4 を同じ順で行うが、Inspect に使った input session を実行まで保持する。
Program 確定後に component の `resource.Request` と queue から予約量を計算し、全 reservation が
成功した後にだけ output session/transaction を acquire する。したがって output acquire 失敗では
input session と reservation を逆順に解放し、Compile/solve 失敗では output に触れない。

### WAVE の読み側 scope

- `plugin/wave` を独立した official plugin とし、WAVE Format、demux component、read trait、必要な
  configuration を同じ package family に集約する。filesystem Provider や PCM plugin を import
  しない。
- Inspect は RIFF/RF64 header、`ds64`、`fmt `、`data`、chunk size、word padding を checked arithmetic
  で検証する。malformed、unsupported、truncated を区別できる diagnostic にする。
- 最初の実経路は uncompressed PCM とする。Inspect は header から sample properties、sample-rate
  time base、format tag、data range を確定し、input carrier descriptor に media properties が無くても
  output descriptor を作れることを条件にする。
- demux は `access.Bytes()` を消費し `format.Chunks()` を生成する。`buffer.Handle.Range` で表現できる
  完全な範囲は zero-copy で渡し、header または item 境界を跨いで再構成が必要な部分だけ Job grant
  から copy する。派生 handle を保持する期間も既存の downstream queue grant 勘定内に収める。
- `_legacy/plugin/wave/internal` は RIFF/RF64 の規格処理と数値検証を読むためだけに使う。旧 operator、
  API、package を復活させず、移植が完了したファイルは `_legacy` から削除する。
- M6-2a の explicit graph は WAVE demux と linear PCM parser を明示する。codec Binding による自動
  選択は M6-2c の担当であり、この単位の green 経路をそれに依存させない。

## 手順

### 1. trait store を CompileContext と共有する

- `plugin` の component trait slot を marker-keyed store として切り出し、Component と
  CompileContext が同じ key/duplicate/type-erasure 規則を使うようにする。
- component 用の `WithTrait`/`TraitValueOf` の互換 shim は作らず、既存 API を新しい内部表現へ
  そのまま移す。
- `media/format` に Inspect 結果を attach/recover する型付き関数を置き、他 package が低水準 store
  を直接読まないことを package test で固定する。

### 2. Inspect contract を Format read trait に足す

- Inspect の input を、選択済み opening と bounded lifecycle context に限定する。
- Inspect result の validity、clone/immutability、Format identity との対応を検証する。
- Inspect の無い Format と、Inspect 必須なのに結果が無い component を区別し、後者は Compile 前の
  構造化 diagnostic にする。

### 3. Host lifecycle を再構成する

- M6-1 の bind/compile/acquire が混ざった resolve 経路を、input acquire、inspect、compile/solve、
  reservation、output acquire の段階へ分ける。
- `Host.Plan` と `Host.Prepare` が共通の pure planning 段階を使いつつ、所有する resource の差が
  明示されるようにする。
- failure matrix に各境界を追加し、input close、reservation release、output abort/close が逆順かつ
  bounded cleanup context で一度だけ走ることを検査する。

### 4. CompileContext を graph/solver 全体へ渡す

- explicit node の Shape/Compile と、solver が行う再 Compile が同じ node-local context を使う。
- 候補 component の config 探索や memoization key に Inspect の mutable identityを入れない。同じ
  snapshot から同じ compilation が得られる pure contract を維持する。
- Inspect call count と Compile call count を計測する fixture を置き、Inspect 1 回に対して Compile が
  複数回でも結果が変わらないことを固定する。

### 5. WAVE Inspect と demux を実装する

- RIFF/RF64 chunk reader を I/O lifecycle から分け、byte slice/range に対する pure parser として
  test できる構造にする。
- Format read trait の Inspect から header parser を呼び、実行 demux が再解析せず使える immutable
  plan を CompileContext 経由で渡す。
- demux operator の ownership、padding、partial read、EOF、cancel、grant cleanup を test する。

### 6. WAVE file から raw PCM file への経路を通す

- 実 filesystem Reference を input/output に使い、WAVE demux、明示 linear parser、既存 PCM 経路、
  raw PCM writer を一つの Job で実行する。
- 出力 sample bytes と descriptor の properties/time base が header と一致し、carrier fixture が
  properties を付けていないことを検査する。
- Fast と Realtime の両 preset で同じ経路を通し、Inspect が増えても payload reservation と
  cleanup に退行が無いことを固定する。

## 検証

```bash
go test ./plugin/ ./media/format/ ./host/ ./internal/graph/ ./internal/solve/ ./plugin/file/ ./plugin/pcm/linear/ ./plugin/wave/ -race
go vet ./plugin/ ./media/format/ ./host/ ./internal/graph/ ./internal/solve/ ./plugin/file/ ./plugin/pcm/linear/ ./plugin/wave/
go build ./...
gofmt -l .
go run ./tools/cmd/docs-check
```

追加で次を検査する。

- `Host.Plan` が input session を Acquire/Inspect/Solve の間だけ保持して必ず閉じ、output session と
  transaction を一度も acquire しない。
- `Host.Prepare` が input session を Inspect から Run まで同じ snapshot で保持し、resource 予約後に
  だけ output を acquire する。
- Inspect が node ごとに一度だけで、solver が Compile を複数回呼んでも再 Inspect せず同じ結果を
  得る。
- RIFF/RF64 の chunk size、`ds64`、padding、overflow、truncated header/data が bounded に失敗する。
- media 意味を持たない file carrier descriptor から、WAVE header の事実だけで PCM descriptor が
  確定する。

**単位完了 gate:** 明示指定した実 WAVE file を読み、実 raw PCM file へ正しい sample bytes を
書き出す end-to-end test が green である。Probe、自動 Format 判別、positioned write、WAVE mux、
spool、RIFF INFO、未知 chunk preservation、Binding 駆動選択は後続単位へ残す。
