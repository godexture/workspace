# M6-4: standard composition と public plugin testkit

M6 の composition/quality 単位。この文書は実装手順であり、公式 composition と拡張性は
[plugins.md](../plugins.md#m6-完了条件)、testkit と integration は
[quality.md](../quality.md#m6-完了条件)、利用者・plugin author の体験は
[experience.md](../experience.md#m6-完了条件) を正本とする。

> 状態: **完了**（手順 1–7 完了）

## 目的

M6-3 までに WAVE、linear PCM、RIFF INFO、local file Provider の実経路は成立したが、利用者は各
definition と Binding を自分で列挙しなければ公式 Host を構成できない。また end-to-end test が
foundation や個別 plugin package から別の公式 plugin を import しており、第三者 plugin と同じ公開面で
公式 family を検証できていない。

M6-4 は公式 definition を一つの `plugin.Set` にまとめる `standard` package、definition だけを検査する
構造層と typed fixture を実行する意味層に分かれた public `testkit`、dependency graph の最上位にある
`integration` module を追加する。公式 component と out-of-tree 相当 component を同じ testkit と Host で
実行し、core を変更せず `standard.Set().Add(acme.Plugin())` だけで拡張できることを固定する。

## 決定

### definition が自分の declaration を運ぶ

- `plugin.Definition.WithDeclarations` は immutable な新しい definition を返し、definition 内部の Binding と
  vocabulary declaration を component と同じ値で運ぶ。`plugin.Set.Add` は owned declaration を自動的に
  composition へ加え、利用者に種類別の追加操作を要求しない。
- invalid declaration と同じ definition 内の duplicate key は捨てず、definition の problem と宣言値を
  Host 構築まで保持する。異なる definition が同じ key/target を宣言することは既存どおり許容し、異なる
  target は明示 override が必要な conflict にする。
- owned declaration の target を owner definition 内へ制限しない。第三者 plugin は公式 component を
  target にできる。公式 family 間 Binding が `standard` に属するのは、公式 plugin 同士の直接 import を
  避けるためである。
- plugin identity を `Remove`/`OverridePlugin` したときは owned declaration も同じ寿命で除去・置換する。
  component identity だけを `Remove` して target が消えた場合は declaration を残し、catalog が missing
  target と owner definition の両方を診断する。暗黙に declaration まで削除しない。
- `linear.Plugin()` と `wave.Plugin()` は自身の Binding と依存 vocabulary を own し、各 `Set()` は
  `plugin.NewSet(Plugin())` まで縮める。`Set.AddDeclaration` は family 間 Binding 等を置く composition root
  用として残す。

### `standard` は唯一の公式 composition を返す

- `standard.Set() plugin.Set` は WAVE、linear PCM、local file Provider の definition を、codec/metadata
  Binding を含む完全な公式 composition として返す。利用者に family ごとの import、Binding、trait の
  種別を列挙させない。
- `standard.NewHost(extra ...plugin.Definition)` は `Set()` へ extra definition を `Add` し、
  `host.New(host.Plugins(set))` を呼ぶだけの convenience とする。別 catalog、global registry、暗黙の
  process state、種類別 option を持たない。
- extra の duplicate/invalid definition は `plugin.Set` と Host の既存 composition diagnostic をそのまま
  返す。last-wins や公式 definition の暗黙 override を convenience に作らない。
- `standard` は公式 plugin を束ねる dependency graph 上位 package とし、foundation と個別 plugin から
  import しない。`standard.Convert` と CLI は M6-5 に残す。

### public testkit は構造層と typed case 層に分ける

- `testkit.Plugin(t, definition)` は definition 一つから構造的に判定できる範囲だけを検査する。identity、
  descriptor、config schema、trait と port shape、execution binding と shape、trait-only component の
  validity を対象とし、実 byte や意味的 conformance を検査したと主張しない。
- `Plugin` の godoc、subtest 名、失敗 message に「structural validation only; typed cases are required for
  conformance」に相当する範囲を明示する。成功を conformance certificate として表す API、report、名称を
  作らない。
- `Spec` の型消去を逆向きに復元する hook、dummy descriptor/config、fixture を持つ production
  `plugin.Definition`、公式 plugin だけが使える internal helper は追加しない。
- typed case は subject となる typed component/trait と、config、入力 fixture、期待値を受ける。subject を
  除く author 側の case 記述はこの三つに限定する。Host 構築、`plugin.Set` の補助 component、Job/graph、
  Access Reference、queue、grant、item の `Share`/`Release`、Plan inspection、cleanup は testkit が所有する。
- Provider の外部状態や reference が必要な場合は、typed input fixture が seed/readback の方法を表す。
  fixture は test 実行用の型付き値であり production definition へ入れず、Host/Job/queue/ownership を author
  へ露出しない。公式 local file case は testkit が temporary directory と Reference を作る。
- author が config、入力 fixture、期待値以外の scheduler、queue、manual `Release`、surface DTO、Plan
  traversal を書かなければ検査できない箇所が見つかった場合は helper を足す。足さない場合は理由と
  author 側の追加負担をこの task と [experience.md](../experience.md#m6-完了条件) に記録する。

### 共通 contract は一つの runner が実行する

- typed `Component`、`Format`、`Codec`/`Parser`、`Metadata Encoding`、`Access Provider` helper の共通
  実行を一つの package-private runner に置き、kind と typed adapter/case で parameterize する。helper ごとに
  Host lifecycle、queue drain、cancel、ownership accounting を複製しない。
- runner は identity/descriptor/config、Compile purity/repeatability、bounded Suggest、selected component
  だけの Open、cancel/EOF/Flush/Finalize/Close、declared schema と実 item、ownership leak/double drop、
  panic/error boundary、empty/truncated/oversized fixture を共通に扱う。
- kind-specific helper は共通 runner に subject adapter と追加 assertion だけを渡す。Format は bounded
  Probe、capability alternative、unknown carrier、topology、Codec/Parser は chunk boundary、invalid packet、
  delay/Flush、timestamp/final parameters、Access Provider は capability 選択、Own/Borrow、commit/abort を
  追加する。
- Access Snapshot の再取得と retry は実 consumer となる remote Provider の milestone に残す。M6-4 では
  consumer の無い session operation を足さず、coverage registry に contract と担当 milestone を記録する。
- direct source と Inspect 必須 Format の組み合わせは、session/capability model へ統合する M9 まで専用
  diagnostic で失敗させる。一般的な Inspect opening failure に畳み込まず、coverage registry に M9 担当の
  未 cover contract として記録する。
- RIFF INFO の Metadata Encoding は trait-only component なので data-path `Open` を捏造しない。共通 runner
  の control-plane kind として identity/config/cancel/panic/invalid fixture を共有し、追加 helper が
  parse/marshal、duplicate/order、unknown raw を検査する。Mapping と loss は M7 に残す。
- M6 で実 consumer の無い Endpoint helper は作らない。Endpoint の lifecycle/clock/overflow/reconnect
  conformance は M9 に残す。

### 公式 typed case の覆い漏れを integration で拒否する

- `integration` は独立した nested module とし、root、`standard`、公式 plugin、public `testkit` を import
  できる dependency graph の最上位に置く。`go.work` に追加し、tracked source から起動する
  `tools/cmd/test-runner` の通常探索対象に含める。
- integration は `standard.Set()` の全 component を列挙し、`ComponentView.Executable()` が true の公式
  component identity が typed case registry に一件以上存在することを検査する。registry の key は marker
  由来 identity とし、display name、package insertion order、手書き duplicate list に依存しない。
- coverage registry は「case が存在する」ことだけでなく、その case を同じ test run で実際に共通 runner
  へ渡す。未登録 identity、存在しない identity、同じ identity の意味のない重複を diagnostic にする。
- M6 で未 cover の専門 contract は安定した contract identity と担当 milestone を registry に登録する。
  担当の無い未 cover、重複、空の identity/milestone を拒否し、M10 が未 cover の残存を機械的に失敗させられる
  完了検査を持つ。この一覧を public testkit の最終状態表との差分とする。
- trait-only RIFF INFO component は executable coverage の母集団には入らないが、M6 の Metadata case と
  structural case を明示登録して実行する。`Executable() == false` を semantic coverage の免除と誤認しない。
- foundation と個別公式 plugin の test から、別の公式 plugin や `standard` を必要とする end-to-end、
  composition、identity test を integration へ移す。個別 package には単独の algorithm/contract unit test
  だけを残し、integration fixture を import させない。

### 仕様 vector と第三者拡張を同じ入口で検証する

- WAVE は conformance 相当の小型 RIFF vector、未知 chunk と RIFF INFO を含む byte-exact roundtrip、
  malformed/truncated input を typed Format case で検査する。
- linear PCM は複数 valid bits と left-justify を含む vector、chunk boundary variation、decode/encode の
  logical output exact を typed Codec/Parser case で検査する。
- RIFF INFO は仕様 vector、duplicate/order、unknown raw の parse/marshal roundtrip を typed Metadata case
  で検査する。local file は source/sink capability 選択、transaction commit/abort と cleanup を typed
  Access case で検査する。Own/Borrow は direct fixture で authority と Close 回数を検査する。
- integration 内に第三者相当 module/package fixture を置き、新しい schema、Format、Codec、Metadata
  Encoding、Access Provider を marker/config/Compile/Open/trait/Binding だけで宣言する。公式 package の
  unexported helper、internal package、global registrationを使わない。
- 利用者側は `standard.Set().Add(acme.Plugin())` だけで Host を作り、第三者 Provider の reference から
  第三者 Format/Codec/Metadata を通る実変換を行う。`host.Providers` 等の種類別 composition や
  foundation/core source の変更を要求しない。
- 旧 import-path snapshot は、integration から実 marker identity と期待 package path を照合する test へ
  置き換える。official family の rename/move が identity を黙って変えないことを固定する。
- conformance 実行後、[capability.md](../capability.md) の WAVE、PCM、RIFF INFO、local file 行へ確認済みの
  test を記録する。旧実装との一致を正しさの根拠にしない。

## 非目標

- `standard.Convert`、path convenience、input hint/fallback policy、CLI は M6-5 が担当する。
- Metadata Mapping/loss report は M7、Endpoint testkit と surface は M9、MP3/FLAC/filter family は M8 に
  残す。
- Access Snapshot の再取得と retry は remote Provider の milestone、direct resource の session/capability
  model への統合は最初の stdin/stdout consumer を持つ M9 に残す。
- root CI matrix、外部 full corpus、hermetic build、SBOM/NOTICE/release plan、全 example の snippet compile
  は M10 に残す。
- public testkit に型消去 execution hook、production fixture registry、golden downloader、benchmark framework、
  official-only escape hatch を追加しない。

## 手順

### 1. owned declaration contract を実装する

- `Definition` に immutable declaration storage と `WithDeclarations`/`Declarations` を追加し、Set の
  Add/Remove/OverridePlugin/OverrideDeclaration に ownership と problem retention を反映する。
- catalog の missing target diagnostic に target component と owner definition を載せる。owner 外 target、
  equivalent cross-definition declaration、invalid/duplicate、component/plugin Remove を検査する。
- linear/WAVE の Binding と vocabulary を各 definition へ移し、`Set()` を `NewSet(Plugin())` に縮める。

**途中 gate:** `linear.Set()` と `plugin.NewSet(linear.Plugin())`、`wave.Set()` と
`plugin.NewSet(wave.Plugin())` がそれぞれ同じ catalog fingerprint を持つ。component target だけを外すと
owner 付き diagnostic になり、definition 全体を外すと owned declaration も消える。

### 2. 公式 composition を一つの Set にする

- `standard.Set()` と `standard.NewHost(extra ...plugin.Definition)` を追加し、WAVE、linear PCM、file、
  codec/metadata Binding が一つの immutable composition から Host を作ることを検査する。
- definition の順序と repeated call が deterministic で、異なる Host が state を共有せず、extra の
  duplicate/invalid diagnostic が既存 Host contract を維持することを検査する。

**途中 gate:** `host.New(host.Plugins(standard.Set()))` と `standard.NewHost()` が同じ catalog を持つ
Host を作り、M6-3 の WAVE/raw walking skeleton が既存 test で green のままである。

### 3. 構造層 testkit を公開する

- root `testkit` package に structural-only `Plugin` helper を置き、公開 catalog construction と component
  view から definition の構造を検査する。
- godoc、subtest、failure message で範囲を明示し、invalid identity/schema/trait/execution/control-plane
  fixture を使って aggregate diagnostic を検査する。

**途中 gate:** 公式三 definition と第三者相当 structural fixture が同じ `testkit.Plugin` を通り、意味的に
壊れているが構造上 valid な fixture を「conformance 済み」と報告しない。

### 4. 単一 runner と M6 の typed helper を実装する

- typed case の共通 state machine を一つ実装し、component kind/adapter で parameterize する。Host/Job/Plan、
  queue、grant、ownership、cancel、EOF/finalization、failure cleanup の implementation を helper 間で共有する。
- `Component`、`Format`、`Codec`/`Parser`、`Access Provider` helper を共通 runner の薄い入口として追加する。
  Metadata helper は trait-only path を同 runner へ接続し、RIFF INFO の追加 contract だけを持つ。
- direct source と Inspect 必須 Format の組み合わせを Plan/Prepare 時の専用 diagnostic にし、M9 の未実装箇所を
  一般的な opening failure と区別する。
- case public surface を config、typed input fixture、typed expectation に限定する。公式 case を書く過程で
  author 側に runtime plumbing が漏れた場合は共通 helper へ戻す。

**途中 gate:** common lifecycle/failure fixture の一箇所の変更が全 executable kind へ適用され、各 kind
helper に queue drain、manual Release、Host close の複製がない。typed case の呼び出し側は subject、config、
input、want だけを記述する。

### 5. 公式 conformance case と coverage gate を追加する

- WAVE、linear PCM、RIFF INFO、file の typed case を public testkit で記述し、仕様 vector、roundtrip、
  truncation、boundary、transaction failure を検査する。
- executable official component identity と実行済み typed case identity を比較する coverage test を追加する。
  RIFF INFO の trait-only case と structural cases も別 assertion で必須にする。
- coverage registry に M6 で未 cover の Snapshot/retry、direct＋Inspect、Mapping/loss、Endpoint contract と
  それぞれの担当 milestone を登録する。担当の無い gap を拒否し、M10 の完了検査が残存 gap を列挙して
  失敗することを固定する。
- 個別 official package の cross-plugin end-to-end test を integration へ移し、package-local unit test の責務を
  algorithm と単独 contract に戻す。

**途中 gate:** `standard.Set()` に executable component を一つ追加して typed case を登録しない test fixture
が coverage failure になり、公式全 component の登録済み case は実際に共通 runnerを通る。

### 6. integration module と out-of-tree 相当 plugin を接続する

- `integration/go.mod` を作り `go.work` へ追加する。official WAVE↔PCM file end-to-end、identity snapshot、
  typed coverage を dependency graph 最上位へ置く。
- third-party fixture family を integration 内だけで実装し、`standard.Set().Add(acme.Plugin())` で Provider、
  Format、Codec、Metadata Binding を含む実経路を構成する。
- foundation/official plugin の production/test import graph に逆向き dependency や official cross-import が
  残っていないことを構造 test で固定する。

**途中 gate:** root/official package を変更せず第三者 fixture の入力から期待 output まで変換でき、同じ
fixture が structural test と typed case を通る。

### 7. 体験、capability、milestone gate を記録する

- typed case author が書く概念と記述量を実測し、config/input/want を超えた負担が無いこと、Host/Job/Plan、
  scheduler/queue/manual Release/surface DTO を書いていないことを `experience.md` に記録する。
- 公式 component source の概念数と手書き string identity/cross-plugin dependency の不在も M6 体験実測へ
  合わせて記録する。差があれば helper または採らない理由を残す。
- `capability.md` の M6 対象行へ実行した conformance/roundtrip/transaction test を記録し、checkpoint と
  この task を完了にする。

## 実装結果

- `plugin.Definition` が owned declaration を immutable に運び、linear/WAVE の family 内 declaration は
  `Plugin()` に集約した。`standard.Set()` は file、linear PCM、WAVE と family 間 codec Binding を一つの
  composition として返す。
- `testkit.Plugin` の structural-only 層と、共通 runner を使う Component/Format/Codec/Access/Metadata の
  typed case 層を実装した。Plan/Run failure の段階、deadline に対する Compile purity、cancel、EOF、
  Finalize/Flush/Close、ownership、transaction を runner が所有する。
- coverage registry は公式 executable 全件の実行済み case と trait-only identity を検査し、未 cover contract
  を担当 milestone 付きで保持する。Snapshot/retry は remote Provider、Mapping/loss は M7、direct＋Inspect と
  Endpoint は M9 である。
- integration module は RIFF/Extensible WAVE、12/16-bit PCM、RIFF INFO/未知 chunk、local file transaction、
  Fast/Realtime、probe replay、tag-driven parser selection を公開面から検査する。foundation と個別公式 plugin
  の逆向き/cross-family import は AST test で拒否する。
- 第三者相当 ACME plugin は公式/internal helper を使わず、Access Provider、read/write Format、Codec、
  Metadata Encoding と owned Binding を一つの definition で運ぶ。利用者側の合成は
  `standard.Set().Add(acme.Plugin())` だけである。
- typed case の実測と、immutable-reference Provider fixture を一行へ縮めた判断は
  [experience.md](../experience.md#m6-4-の実測) に、確認済み能力は [capability.md](../capability.md) に記録した。
- 対象 package と integration の race/vet、root build、全 workspace の `test-runner --simd`、gofmt、
  docs-check はすべて通過した。

## 検証

```bash
go test ./testkit/ ./standard/ ./plugin/file/ ./plugin/pcm/linear/ ./plugin/wave/ -race
go test ./... -race                          # integration module 内
go vet ./testkit/ ./standard/ ./plugin/file/ ./plugin/pcm/linear/ ./plugin/wave/
go vet ./...                                 # integration module 内
go build ./...
go run ./tools/cmd/test-runner --simd
gofmt -l .
go run ./tools/cmd/docs-check
```

追加で次を検査する。

- `standard.Set()`/`NewHost()` の公式 catalog が完全で deterministic、extra definition が `Add` 一つで
  Access/Format/Codec/Metadata を一緒に運ぶ。
- `testkit.Plugin` は structural-only と明示され、typed case が無い executable official component を
  integration coverage が必ず失敗させる。
- Compile purity/repeatability、Open selection、cancel/EOF/Flush/Finalize/Close、ownership leak/double drop、
  panic/error boundary の実装が一つの runner にだけあり、kind-specific helper は追加 contract だけを持つ。
- typed case author の入力が subject、config、input fixture、expectation に閉じ、Host、Job、graph、queue、
  grant、manual `Release`、Plan traversal、surface DTO を書かない。
- WAVE/PCM/RIFF INFO の仕様 vector と exact roundtrip、file transaction、Fast/Realtime の実経路が green。
- executable official component 全件の typed case、trait-only RIFF INFO case、marker import path identity が
  integration で実行される。
- 未 cover contract は coverage registry に担当 milestone とともに現れ、Snapshot/retry は remote Provider、
  direct＋Inspect と Endpoint は M9、Metadata Mapping/loss は M7 として判別できる。direct＋Inspect は M9
  まで専用 diagnostic で失敗する。
- out-of-tree 相当 plugin が internal packageや official plugin helper を使わず、core/standard を変更せずに
  `standard.Set().Add(acme.Plugin())` だけで Host と実変換へ載る。
- foundation と個別 official plugin の test import graph が別 official plugin、`standard`、integration を
  逆 import しない。

**単位完了 gate:** `standard.NewHost()` が公式 WAVE/linear PCM/file composition を構築し、公式の全実行
component が public typed case で検証される。仕様 vector と実 file end-to-end が integration module で
green になり、第三者相当の Provider/Format/Codec/Metadata を持つ definition が core 無変更の
`standard.Set().Add(acme.Plugin())` 一つで同じ経路へ載る。typed case author は config、入力 fixture、
期待値以外の runtime plumbing を実装しない。
