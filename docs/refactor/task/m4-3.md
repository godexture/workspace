# M4-3: bounded solver、Plan、private Program

M4 の第 5 単位。この文書は実装手順であり、探索規則の正本は
[planner.md](../planner.md)、policy/variant は [performance.md](../performance.md)、
phase 順と Program 境界は [runtime.md](../runtime.md#planner-pipeline) とする。

## 目的

M4-2 の explicit graph compiler を一つの semantic authority として再利用し、requested
edge の unmet `Requirement` にだけ bounded bridge 探索を行う。選択結果を inert な public
`Plan` と実行可能だが module 外へ出ない `Program` に分離し、walking skeleton を
Plan/Program 経由で引き続き同じ bytes、順序、timestamp のまま通す。

Access acquire/probe/inspect、output transaction、runtime queue、execution island、Finalize
実行はこの単位に入れない。Provider/Endpoint binding と実 PCM は M4-4 が実 consumer として
確定する。

## 決定

### public request と policy

- user request の policy は `job` が所有する。`Preset` と展開後の直交 vector を分け、
  default は `Fast + Repeatable + ArtifactNone + Preserve` とする。
- planning `Budget` も request/Host policy の immutable value とし、states、component
  compiles、suggestions per need、fixpoint iterations、defensive duration を別々に制限する。
  zero/magic fallback を solver 内へ散らさず、一つの default constructor で展開する。
- M8 まで実 explicit variant が無いため、複数 variant の export を consumer 無しで凍結
  しない。M4 は各 Spec が宣言する一つの implementation contract を implicit default
  variant として扱い、Plan には component identity から導いた安定 ID と contract を記録
  する。複数 variant API は M8 の scalar/SIMD consumer と同時に追加する。

### canonical descriptor state

- `property.Set` は値の挿入時に宣言済み canonical encoder を実行して immutable bytes を
  保持する。fingerprint 時に arbitrary value、reflection、format 済み文字列を推測しない。
- descriptor fingerprint は domain-separated SHA-256 とし、stream ID、schema marker、
  time base、sorted property key/canonical value、metadata scope を length-prefix で含める。
  alias、pointer、factory、diagnostic text は含めない。
- visited map は fingerprint だけで同一視せず、同じ digest bucket 内で fingerprint 対象の
  state equality を確認する。未知 third-party property も同じ経路へ参加する。

### solver

- `internal/solve` は default port shape から single-input/single-output bridge 候補を schema
  identity で索引する。全 component を各 state で走査しない。requested multi-input node は
  維持するが、solver が multi-input/content/topology node を発明しない。
- explicit graph evaluation は `internal/graph` に集約する。通常 Compile は schema mismatch
  と Requirement を diagnostic にする一方、solver 用 evaluation は同じ compile loop から
  typed gap を返す。config resolve、Shape、Compile の別実装を `solve` に複製しない。
- gap の現在 descriptor がそのまま downstream Compile を満たせる場合は bridge 0 本を
  選ぶ。そうでなければ priority queue、descriptor fingerprint ごとの best rank、compile
  cache を使う Dijkstra 型探索を行う。
- config 候補は default と bounded `Suggest` だけとし、すべて同じ schema resolve と
  `Compile` を通す。Open/Close は候補評価で一度も呼ばない。
- auto insertion を許すのは Structural と、明示 Need を満たす Representation/Compression
  effect だけとする。Content/Timeline/Topology effect は requested node でない限り拒否する。
- rank は hard filter、preservation、copy、loss、implementation contract、resource goal、
  step 数、canonical identity/config の lexicographic 順とし、単一の加重 score を作らない。
- state/compile/suggestion/fixpoint のいずれかを使い切った場合は `solve.budget-exhausted`、
  候補を探索し切った場合は `solve.unsupported` とする。Need、使用量、上限、bounded rejection
  summary を structured detail に残す。

### Plan と Program

- public `plan.Plan` は requested/auto node と edge、component/implicit variant identity、
  redacted canonical config summary、input/output descriptor projection、insertion reason、
  Effect、resource request/estimate、requested/effective policy、budget usage、catalog/platform
  snapshot、execution signature、fingerprint を持つ。
- Plan へ `config.ResolvedView.Value`、`stream.Descriptor` の private factory、function、pointer、
  raw secret を格納しない。DTO 化できる inert value だけを持ち、getter は slice/map を copy
  する。
- `internal/program.Program` は resolved config、private component compilation、dense
  topological node index を保持する。serialize/export せず、Open は Program に選ばれた
  compilation だけを component へ渡す。
- Plan fingerprint は表示 alias と diagnostic 文言を除く canonical execution description
  から作る。同じ request/catalog/policy/platform なら catalog insertion order、map order、
  candidate enumeration orderに依存せず一致する。

## 手順

### 1. property/descriptor fingerprint と policy value を実装する

- property canonical bytes の insertion-time validation、immutable copy、Set equality/fingerprint
  を追加する。
- stream descriptor fingerprint と collision-confirmation 用 state equality を追加する。
- job policy/preset/budget と plugin implementation contract を追加し、invalid/unsupported
  vector を structured diagnostic にする。

### 2. graph evaluation と bridge solver を実装する

- M4-2 compiler を complete graph と typed gap の両方を返せる内部 evaluator に分解する。
- schema gap、descriptor Requirement、multi-input fixpoint を同じ worklist へ載せる。
- candidate index、priority queue、visited best rank、compile memo、budget accounting を実装する。
- direct path、one bridge、long bridge、non-progress、unsupported、各 budget exhaustion、
  catalog/order determinism を test する。

### 3. Plan/Program を構築する

- config の redacted summary、descriptor inert projection、Plan immutable model/fingerprint を
  追加する。
- resolved graph から public Plan と private Program を同時に構築し、両者の node/edge/
  fingerprint 対応を test する。
- `Host.Plan(ctx, job)` を explicit graph の read-only public entry point として追加する。
  input/output binding が必要な Job は M4-4 まで明示 diagnostic にする。

### 4. walking skeleton を Plan/Program 経路へ移す

- data path と metadata path を solver へ渡し、Program からだけ operator を Open する。
- 少なくとも一つの required descriptor gap を auto component で補完し、その node と理由が
  Plan に現れることを確認する。
- bytes、item 数、順序、timestamp、property、metadata raw preservation の assertion を維持
  する。
