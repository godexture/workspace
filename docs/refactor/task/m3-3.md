# M3-3 実装指示書: 残る拡張点と consumer を持たない contract の確定

M3 の最終単位である。M3-1 が縦断経路、M3-2 が metadata を担当した。ここでは残る拡張点を置き、M3 全体の完了判定を行う。

前提、必読、スコープ境界、中断条件は [m3-1.md](m3-1.md) と同じである。contract の意味は [access.md](../access.md) と [scope.md](../scope.md) を読む。この文書はそこに書かれていない制約だけを述べる。

## この単位の最優先規則

**実装する consumer がない contract を完成させない。**

[access.md](../access.md#m3-完了条件) は「clock domain と timestamp origin、latency/buffer range、block/drop/duplicate/conceal policy、reconnect/discontinuity semantics、exclusive/shared resource、hotplug event、multi-output の `AllOrNothing` 共同 transaction は、設計として記述するが実装する Endpoint も Provider も現時点の roadmap に存在しない。M3 では最小の型だけを置き、詳細は実際の Endpoint を作る milestone で決める」と明記している。理由も同じ節にある。現行 `MediaAttributes` が「使われないまま形だけ先に決めて後で作り直す」失敗をしたからである。

他の単位では「条件を満たすまで作る」ことが正しかったが、この単位では**足りない方に倒す**のが正しい。設計文書に書いてあるからという理由で field を増やさない。M3-1 の review で `schema.Pipe`/`Tee` や erased な per-item API が consumer を持たないまま export され、削除することになった。同じことを繰り返さない。

判断に迷ったら、その型を今日 test 以外の誰が呼ぶかを問う。答えられなければ置かない。

## 既存の機構を再利用する

新しい仕組みを作る前に、M3-1/M3-2 が用意した口を使う。重複を作った場合は差し戻す。

- component の登録と conflict 検出: `plugin.Declaration` と `internal/catalog`。Provider や Endpoint のために別 registry を作らない。
- identity 導出: `internal/marker`。`access`/`endpoint` 独自の marker 解析を書かない。
- clone 規則: `internal/snapshot`。reference 型を値に持つ宣言は同じ規則に従う。
- capability 語彙: `access.Capability`/`Alternative`/`Requirements` は既にある。`endpoint` 側に同じ enum を再定義しない。
- 借用と共有: `media/buffer.View`/`Handle` と `flow.Input` が確立した「accessor は借用を返し、共有は明示」の形に合わせる。

## 作業単位

### 1. `media/side`

packet/frame の side data。`media/packet` と `media/audio` の item が side data を持てるようにする。

値の型は第三者が core 無変更で足せること、reference 型は clone 宣言が要ることが要件である。`media/metadata` の key 機構と同じ形になるはずなので、**同じ規則を三度目に書き写さない**。共有できる部分は `internal` へ寄せるか、既存機構をそのまま使う。

hot path に載る型なので、side data を持たない item が追加の allocation や間接参照を払わない形にする。

### 2. `stream.Event`

live topology を `stream.Descriptor` の mutation ではなく event で表す。stream の追加・削除・property 変更を表現できればよい。

新しい stream を follow/ignore/fail のどれにするかは [D3](../decisions.md) として延期されている。**既定を決めない。** 型の上で「まだ決まっていない」ことが分かる形にする。

### 3. `access` の残り

現在 `access` には capability、`Own`/`Borrow`/`Factory`、`Resource` がある。残りを足す。

- `Reference` — canonical target と、policy に従う redacted display を分ける。credential や signed URL が public 表現へ出ない形にする。
- `Provider` — reference を source/sink へ解決する control-plane 宣言。scheme の重複は host 構築 error にする（`plugin.Declaration` に乗せる）。
- transaction — sink を `io.Writer` ではなく transaction として表す。transaction class（atomic replace、staged commit、rollbackable、append-only、live/no-commit）を宣言できるところまで。**実行と rollback は M5。**
- spool — 隠れた実装詳細ではなく、予測 bytes、memory/disk、開始 latency、rollback class を伴う明示的な要素として表現できること。**最初の挿入 consumer は M6 の file/WAVE 経路。**
- bounded probe view — immutable で cursor を変更しない view と、追加 range request の表現。**実際の shared probe 実行は M6。**
- snapshot identity — strong snapshot を持たない source がその事実を残せること。

foundation package が filesystem、network、device の具体実装を import しないこと。

### 4. `endpoint`

Endpoint は閉じた `Device` role registry ではなく、通常の typed component として表す。M3-1 で `plugin.Component` が port shape と `Open` を持つようになっているので、その上に trait を足す形になる。

- `FiniteStatic`/`LiveStatic`/`LiveDynamic` と realtime/offline の区別を宣言できること。
- Device は component identity、device reference、device descriptor を分けて表現できること。
- **Host 構築や package import が device scan、permission prompt、network access を起こさないこと。** これは「起こさない」を型と test で示す。enumeration は明示的な opt-in query であり、M3 では query の型があれば足りる。

上の「最優先規則」に挙がっている trait はここでは置かない。

### 5. 分類の確定

[scope.md](../scope.md) の contract 分類節を M3 全体の最終形へ書き直す。

- data path の consumer を持つ contract と、宣言だけの contract を分ける。
- 宣言だけの contract は、**どの milestone がその consumer を作るか**を明示する。担当が書けない contract は、そもそも今置くべきでない。
- [scope.md](../scope.md#m3-完了条件) の capability matrix を一行ずつ照合し、M3 時点で型が存在しない行の担当 milestone を明示する。

## 完了時の記録

この単位で M3 全体が完了するため、逐条確認は 3 文書すべてに対して行う。

1. [media.md](../media.md#m3-完了条件)、[access.md](../access.md#m3-完了条件)、[scope.md](../scope.md#m3-完了条件) の完了条件を逐条で確認する。満たせない項目があれば完了にせず報告する。
2. M4 以降へ送る事項を [checkpoint.md](../checkpoint.md) の注記へ書く。特に「M3 で最小の型だけ置き、詳細を残した contract」がどれで、誰が決めるかを残す。
3. [checkpoint.md](../checkpoint.md) の M3 行を完了へ更新する。
