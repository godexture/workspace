# M6-2c: RIFF metadata と codec Binding 選択

M6-2 の composition/metadata 単位。この文書は実装手順であり、完了条件は
[media.md](../media.md#m6-完了条件) の Metadata/Binding/roundtrip 条項、contract 分類は
[scope.md](../scope.md#m6-の-contract-分類) を正本とする。

> 状態: **未着手**

## 目的

M5 の `metadata.Binding` と `codec.Binding` は composition declaration だけである。metadata encoding
には production の Parse/Marshal contract がなく、codec binding は catalog 検証されても solver の
候補選択に使われない。このままでは WAVE が RIFF INFO を自前で解釈し、同じ chunk schema を受ける
別 codec/parser を format tag と無関係に選べる。

M6-2c は Metadata Encoding を component trait にし、Host が carrier binding を narrow resolver へ
変換して Format に渡す。あわせて WAVE の RIFF INFO と未知 chunk を lossless に保持し、codec tag が
異なる codec/parser だけを solver 候補から除外する。単位終了時には metadata roundtrip と tag 駆動
選択の両方が実 WAVE 経路で green になる。

## 決定

### component は control-plane trait だけを持てる

- 合成時の拡張が component に載る M6-0 の規則に従い、`plugin.Component` は data path を持つ
  component だけでなく、trait だけを持つ control-plane component も表せるようにする。Metadata
  Encoding を Format component へ同居させず、専用 registry、dummy port、dummy `Spec`/`Open` も作らない。
- component が有効なのは「typed `Spec` と非空 port shape を持つ」場合、または「trait を一つ以上
  持つ」場合に限る。`Spec` も trait も無い component は従来どおり Host construction で拒否する。
- 各 component trait は port shape を要求するかを marker-keyed slot の inert descriptor で表明する。
  Access source/sink、Format read/write、Endpoint は port を要求し、Metadata Encoding は要求しない。
  catalog はこの宣言と各 trait 固有の shape 規則を併用し、正当な port-less Encoding と port を
  書き忘れた boundary component を区別する。
- trait-only component は catalog と surface に残るが graph node ではない。`ComponentView.Executable`
  は false、solver の bridge 候補にも入らず、Job が明示 node として指定した場合は
  `internal/graph` が control-plane 専用であることを code 付き diagnostic で報告する。
- `plugin.Compile`/`Component.Open` は trait-only component に対して従来の `ErrComponentSpec` を返す。
  trait 呼び出しを実行 lifecycle の抜け道にしない。

### Metadata Encoding は component trait である

- `media/metadata` が context-aware で pure な Parse/Marshal を持つ `Encoding` trait と
  `plugin.ComponentOption` を定義する。attachment と取得には M6-0 の `plugin.WithTrait` /
  `TraitValueOf` を使い、新しい registry や execution binding を作らない。
- 型消去値を取得する公開経路は `metadata.EncodingOf(component)` に閉じる。Host、catalog、Format
  plugin は低水準 `plugin.TraitValueOf` を直接呼ばない。
- Parse/Marshal は Inspect/Compile の control plane で呼ぶ。`Open`、operator、payload allocator、
  worker grant を要求せず、同じ入力に同じ結果を返す。
- `metadata.Binding` の target component が Encoding trait を持たない場合は Host construction 時の
  composition diagnostic にする。runtime まで「振る舞いのない declaration」を持ち越さない。
- RIFF INFO は小さい control-plane payload として扱う。embedded artwork のように外部入力サイズで
  決まる allocation 上限は [scope](../scope.md#m6-の-contract-分類) に記録した M8 の判断であり、
  この単位で先取りしない。

### Host は narrow metadata resolver だけを渡す

- Host/catalog が carrier ID から `metadata.Binding` target を解決し、その component の Encoding trait
  を取得する。
- Format に catalog、`plugin.Set`、component lookup、service locator を渡さない。Inspect/Compile が
  必要とするのは carrier ID に対する Parse/Marshal だけに限定した immutable resolver である。
- resolver は missing binding、invalid target、Parse/Marshal failure を carrier、binding key、encoding
  identity を含む構造化 diagnostic に変換する。
- WAVE は RIFF INFO carrier identity と raw payload だけを知り、具体 encoding component/package を
  import しない。encoding の差し替えは composition だけで行う。
- M6-2a の Inspect result transport と同じ node-local marker-keyed context を使い、resolver や解析済み
  metadata のために単一 prepared slot、第二の map、Host service bag を作らない。

### RIFF INFO と未知 chunk は順序を保つ

- RIFF INFO encoding は `LIST`/`INFO` の subchunk、word padding、重複 native key、元の順序を扱う。
- 既知 key は `media/tag` の共通 vocabulary へ写像し、各 Entry の `Origin` に encoding identity、
  carrier ID、native key、元 raw block の ID を残す。
- 未知 INFO field と元の INFO block は `metadata.RawBlock` として byte-exact に保持する。意味を解釈
  できないことを理由に破棄・正規化しない。
- WAVE の未知 top-level chunk も raw block として chunk identity、payload、padding、相対順序を復元
  できる形で保持する。`fmt `/`data` と衝突する reserved chunk を未知 chunk として再注入しない。
- 変更のない Document を WAVE へ戻すと、重複、未知 field/chunk、padding、順序が再現されることを
  M6 の lossless roundtrip 条件とする。semantic metadata を編集した時の mapping/loss report は M7
  へ残す。

### codec tag は別 tag の codec/parser だけを除外する

- WAVE Inspect が format tag を output descriptor の canonical codec-tag property に載せる。property
  と canonical encode/fingerprint は `media/codec` が所有する。
- catalog は `codec.BindingKey(tag)` から target identities を引けるだけでなく、各 target がどの tag
  の codec/parser として宣言されたかを逆引きできる immutable index を持つ。
- tagged input に対し、候補 component が一つ以上の codec Binding で codec/parser target として
  宣言され、現在 tag と一致する Binding が一つも無い場合だけ除外する。
- Binding を持たない bridge component は候補に残す。converter、resampler、bitstream filter 等の
  gap-fill を tag filter で塞がない。「Binding target だけを候補にする」という allow-list 規則には
  しない。
- 一つの target が複数 tag に bind されている場合、現在 tag と一つでも一致すれば候補に残す。
  codec と parser の target 順序/role を Binding 宣言どおり保持する。
- tag に対応する Binding が無く graph を解決できない場合は、schema-only の別 codec を選ばず、tag
  と探索 gap を含む planning diagnostic にする。

## 手順

### 1. control-plane component contract を確定する

- `plugin.Component` の validity を Spec+port または一つ以上の trait として定義し、trait descriptor に
  port shape requirement を載せる。既存 Access/Format/Endpoint trait は requirement を明示する。
- `internal/catalog` は port-required trait の空 shape と、Spec/trait のどちらも持たない component を
  composition diagnostic にする。port-less trait は正当な catalog entry として保持する。
- `internal/graph` に control-plane component 専用 diagnostic を追加する。
- surface の `Executable=false`、solver candidate 非掲載、明示 Job node の拒否、`Compile`/`Open` の
  `ErrComponentSpec` を regression test で固定する。

### 2. Metadata Encoding trait を追加する

- `media/metadata` に Encoding value、typed option/accessor、Parse/Marshal context/result を置く。
- M3 foundation test の private encoding interface を production trait の test へ置き換え、重複した
  contract を残さない。
- `internal/catalog` の declaration 検証へ Binding target の Encoding trait 検査を追加する。

### 3. narrow resolver を composition から作る

- catalog の metadata binding を carrier key で immutable に索引し、Format node ごとの resolver を
  Prepare 中に組み立てる。
- resolver を M6-2a の Inspect/Compile context transport へ attach し、Format が carrier ID 以外から
  component を探索できないことを API で固定する。
- binding missing、duplicate/override、target missing、trait missing、parse failure の diagnostic test
  を追加する。

### 4. RIFF INFO encoding を実装する

- `plugin/wave` の Format 実装と分離した encoding component を宣言し、Set 内の
  `metadata.Binding` で RIFF INFO carrier へ接続する。
- Parse は ordered entries、Origin、RawBlock を作り、Marshal は unchanged block を byte-exact に再利用
  する。既知 tag mapping と未知 native key の経路を同じ parser に重複実装しない。
- empty、duplicate key、odd payload、invalid size、truncated subchunk を unit/property test する。

### 5. WAVE Inspect/mux を metadata aware にする

- Inspect は RIFF chunk を走査し、metadata carrier payload を resolver で Parse して output descriptor
  へ載せる。具体 encoding identity を hard-code しない。
- unknown top-level chunk と chunk order を RawBlock/inspection plan に保存し、M6-2b の mux が audio
  data と競合しない位置へ再出力する。
- mux の Compile は descriptor の Document を narrow resolver で Marshal し、runtime operator が
  catalog lookup や metadata semantic mapping を行わないようにする。

### 6. codec tag property と Binding index を追加する

- `media/codec` に typed property と declaration key accessor を置き、descriptor clone/fingerprint へ
  canonical に反映する。
- `internal/catalog` に target-to-tags/roles の逆 index を作り、invalid/duplicate Binding を既存の
  composition diagnostic channel で拒否する。
- WAVE PCM tag と linear codec/parser を composition Binding で接続し、WAVE package から linear
  package への import を作らない。

### 7. solver の候補除外規則を実装する

- candidate lookup の schema index は維持し、その後段で「別 tag に bind された codec/parser target」
  だけを除外する。
- filter の理由を search trace/diagnostic に残し、budget、rank、memoization の deterministic 性を
  変えない。
- matching parser、other-tag parser、unbound bridge を同時に置いた fixture で、matching と bridge は
  残り、other-tag だけが除外されることを固定する。

### 8. metadata roundtrip と tag 駆動選択を通す

- duplicate RIFF INFO、unknown INFO subchunk、unknown top-level chunk、odd padding を含む実 WAVE
  fixture を read -> PCM -> write し、metadata/chunk byte 列と順序を比較する。
- 同じ `format.Chunks()` schema を受ける別 tag の parser/codec を composition へ加え、WAVE header
  tag に対応する linear path だけが選ばれることを Plan と実行結果の両方で検査する。
- Binding を持たない bridge fixture を必要な gap に置き、tag filter 後も挿入できることを検査する。

## 検証

```bash
go test ./media/metadata/ ./media/codec/ ./media/format/ ./internal/catalog/ ./internal/graph/ ./internal/solve/ ./host/ ./plugin/pcm/linear/ ./plugin/wave/ -race
go vet ./media/metadata/ ./media/codec/ ./media/format/ ./internal/catalog/ ./internal/graph/ ./internal/solve/ ./host/ ./plugin/pcm/linear/ ./plugin/wave/
go build ./...
gofmt -l .
go run ./tools/cmd/docs-check
```

追加で次を検査する。

- trait-only component は Host catalog と surface には現れるが `Executable=false` であり、solver 候補や
  graph node にはならない。`plugin.Compile`/`Open` は `ErrComponentSpec`、明示 Job node は専用
  composition diagnostic で失敗する。Spec も trait も無い component は引き続き Host construction で
  拒否され、port-required trait の空 shape も catalog diagnostic になる。
- `metadata.EncodingOf(component)` 以外に production の型消去取り出し口がなく、Binding target が trait
  を持たなければ Host construction が失敗する。
- WAVE が具体 metadata encoding と linear codec/parser を import せず、Set の Binding 差し替えだけで
  resolver と候補選択が変わる。
- tagged input で other-tag codec/parser は除外され、matching target と unbound bridge は候補に残る。
- unchanged RIFF INFO と未知 chunk の byte 列、重複、padding、相対順序が WAVE roundtrip で一致する。
- Parse/Marshal が Open、payload grant、worker task を要求せず、同じ入力に対して deterministic である。

**単位完了 gate:** RIFF INFO と未知 chunk を含む WAVE の metadata roundtrip、および WAVE format tag
に基づく parser/codec 選択の end-to-end test が green である。自動 Format 判別と shared probe は
M6-3、metadata edit/loss report は M7、embedded artwork の control-plane allocation 上限は M8 へ残す。
