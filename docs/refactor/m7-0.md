# M7-0: multi-stream contract

> M7 の最初の production slice を、有限・static な MP4 file-to-file job に限定して確定する。
> この文書は M7 固有完了条件と R-17 traceability の正本である。

## 目的と境界

M7 は、単一 `mdat` の unfragmented MP4 を RandomRead+StableSize source から読み、保存優先で RandomWrite sink へ
remux する。M7-2 の production slice は明示された 1 input/1 output MP4 graph に限定する。音声は
必要な時だけ PCM Binding を通し、decode Binding のない video/subtitle/data track は packet copy する。
M7-3 の standard no-map path は direct reader と writer を固定挿入し、Inspect order の全 track を Many terminal へ渡す。

MP4 は multi-stream execution contract の最初の公式 consumer である。このために closed media role、
heterogeneous item map、packet/item 内の stream identity、item ごとの reflection/string lookup を導入しない。
Serial input buffer のない direct な single synchronous execution island で単一 routed producer が emit する場合だけ、
その call 順を physical mdat の書き込み順として扱う。buffer/fan-out/concurrent producer がある場合の cross-track
physical interleave は契約しない。mux の correctness/exact は track ordinal、`Packet.Sequence`、PTS/DTS/duration、
per-track sample table で判定し、physical interleave の変更を semantic loss としない。ISO BMFF のために全 track の
DTS を比較して global interleave を作ることはしない。

M7 に含めないものは pure sequential/fragmented MP4 と sequential-output boundary spool alternative、rich selector、generic loss DTO、
`ilst` vocabulary mapping/strict mode、graph seek operation、video/subtitle decode、live topology、Endpoint/clock、
stdin/stdout、WASM、`_legacy/` 削除である。別 container の時刻順 fan-in policy も、実 consumer と現実的な
backpressure 設計が現れるまで追加しない。これらは [延期する consumer](#延期する-consumer) まで API を作らない。

## 確定した product semantics

### static topology と inspection

Component topology の正本は construction 時の `Spec.Ports` だけである。全 executable Spec は static な
schema、direction、`One`/`Many`、fan-in policy をここへ宣言する。Inspect 後に port 数や port ID を変える
dynamic Shape、`ShapeContext`、instance Shape snapshot は使わない。

M7-2 の明示 graph は MP4 の source boundary から mux sink boundary まで一つの input と一つの output を
持つ。track cardinality と identity は dynamic port ではなく、static topology の logical `Many` edge を
Open 前に展開した ordered repeated `stream.Descriptor` と private route ordinal で表す。standard が
M7-3 の no-map graph は Many terminal を自動生成する。descriptor は canonical
`stream.ID`、open schema ID、optional timeline、property、metadata を持つ。format-specific raw box、
sample-entry state、inspection provenance は descriptor/item 本体に入れない。

MP4 reader は `bytes` carrier input を持たない direct `RoutedReader` であり、explicit graph の input boundary は
demux の `packets` output を data anchor とする。Boundary の `Component` は Access provider の identity を保持するが、
provider carrier node と carrier edge は Plan/Program に生成しない。Host は provider session を lifecycle 内で一度だけ
Acquire し、その一つの source Opening を Inspect、demux、same-format mux へ共有する。自動 graph は direct reader の
`Many` terminal と writer を固定し、no-map では Inspect order の全 track を preserve-all で接続する。carrier path へ
silent fallback しない。

`format.Inspection` は Format 固有の typed fact を freeze して Compile へ渡す共有 immutable value であり、clone
境界ではない。M7-2 で raw box、sample-entry、metadata carrier を再利用できるのは、Host が同一 format の単一
input inspection を同一 format mux の `CompileContext` へ immutable handoff した場合だけである。Inspection は
format-owned な source range descriptor と bounded な summary だけを保持し、source Opening/I/O handle、raw payload
bytes、sample 数に比例する配列を保持しない。Host は Open 時にだけ元の source Opening を inspected demux と
same-format mux へ貸し出し、Compile と Inspection は I/O を行わない。metadata Resolver のような別の prepared value
は、その型を所有する package が immutability を保証する。複数 input から provenance を推測せず、generic
provenance API は M7 の consumer へ追加しない。Inspect、Compile、Open は catalog や mutable Host service を受け取らない。

### bounded memory と preservation

M7 の constant-RAM は、入力の duration、sample 数、opaque raw payload の長さに依存しない in-memory bound を意味する。
上限が増えてよいのは、明示された track/descriptor、queue、processing page、semantic metadata の cap だけである。
Seek、RandomRead/RandomWrite、Inspect や mux の bounded re-scan は許可する。opaque bytes は Inspection や metadata へ
コピーせず、source range を bounded page で読み出して扱う。

`InspectBytes` は Inspect 中の全 `ReadAt` について、underlying source を呼ぶ前に要求 byte 数を課金する。MP4 の
table scan は固定 page だけを使う。Open 後の lazy sample cursor は Inspect wrapper や残予算を継承せず、Host が
Open-to-Close の間だけ貸し出す元の borrowed source を読む。

WAVE の unknown chunk と trailer は M7 で format-owned source range として preservation し、semantic metadata は
inline value と明示 cap に限定する。cap を超える semantic metadata の扱いは C10 の warning/loss policy に従うが、
opaque range を理由なく drop しない。unfragmented transform mux が sample table や offset の蓄積を必要とする場合は、
Host-owned disk table journal を使う。`job.ResourcePolicy.ScratchMaxBytes` は node ごとの固定 `Compiled.Scratch` claim と
選択済み output spool の maximum を合算した上限で、0 は scratch/spool disabled を表す。claim と aggregate reservation は
Plan と execution fingerprint へ固定する。正の claim を持つ node だけが Open-to-Close の間、node-local borrowed
`plugin.Scratch` を受け取り、Host は operator の Close 後かつ Access session の Close 前に破棄する。table journal、
output boundary spool、output transaction state は quota を共有し得ても別の lifecycle/state である。
offline の `Fast`/`Stable`/`Portable` preset は 64 MiB、`Realtime` は disabled (0) を既定値とする。実際の
claim 分だけ journal を作成し、spool は `AllowSpool` の明示時だけ有効にする。`ScratchMaxBytes` の明示指定で上書きできる。

### logical many edge と typed routed producer

planner は logical `Many` port の repeated descriptors と resolved mapping から、private runtime connection を
descriptor ごとに一つ作る。各 connection は descriptor、stream identity、route/input ordinal、time base を
Open 前に固定する。public graph/Plan は logical port と repeated `PortDescriptor` を投影し、別の topology DTO を
重複して持たない。

typed `Router[I, O]` は各 emitted output item を一つの route ordinal へ送る。一回の `Process`/`Flush` は
複数 item を複数 route へ emit できる。runtime は
Open 時に ordinal を `[]typedDelivery[O]` 相当へ一度だけ解決するため、item loop に port string lookup、
reflection、`any` transport はない。Router 自身は同じ item を fork せず、同じ route の複数 downstream への
fan-out だけを runtime が `Fork` で実行する。

入力 carrier 自体が不要な random-access Format reader は `RoutedReader[O]` として同じ ordinal table へ直接 emit する。
一回の `Read` は複数 route へ複数 item を emit でき、item を emit した call は `nil`、全 item を出し終えた次の
item-less call は `io.EOF` を返す。MP4 demux は現在の track の lazy cursor と route ごとの再利用 item だけを保持し、
全 track 分の page/cursor や sample 配列を常駐させない。MP4 は一 sample の emit 成功ごとに `Read` を返し、後続 sample の
cancel/parse/route error を同じ callback の emit と混在させない。

packet/chunk に `stream.ID`、format 名、selector を追加しない。stream identity は descriptor と private
compiled connection に属し、Router ordinal、parser/codec connection、mux input ordinalが保持する。

### SerialFanIn

新しい public time-ordered merger interface や cross-track timestamp policy は作らない。既存
`flow.Joiner[I, O]` を使い、`SerialFanIn` は input ordinal を保持して callback を一 item ずつ同期直列化する
汎用 fan-in policy とする。これは ordering algorithm ではなく、呼出しを直列化する execution contract である。
Serial input buffer のない direct な single synchronous execution island で単一 routed producer が emit する場合だけ、
emit call 順が physical order になる。buffer/fan-out/concurrent producer がある場合の cross-track physical interleave、
wall-clock 順、再現性は契約しない。同じ input の FIFO と route ordinal はそのまま保持し、これらの構成だけを理由に
generic `SerialFanIn` を Compile で reject しない。

MP4 mux は上記の direct single synchronous execution island でだけ emit call 順を mdat の physical order として扱う。
各 item の track ordinal、`Packet.Sequence`、PTS/DTS/duration から track ごとの sample table を再生成するため、他 route の
availability を待ったり、per-track time base を跨いで DTS を比較したりしない。untimed bytes と timeline-less descriptor を
timestamp order のために reject する契約も持たない。将来 `Stable`/byte reproducibility が必要な consumer は execution
signature と、実現可能な backpressure を備えた別 ordered policy を要求する。別 container が時刻順を必要とする場合も、
その consumer に必要な backpressure を設計した別 ordered policy として後続 milestone で追加する。

> **Superseded history:** 以前の `MergeFanIn` という名称と「全 input head の DTS ordered merge」は close/延期した。
> これは現行の SerialFanIn contract ではない。

### timeline と packet

timeline-less descriptor と timed descriptor を区別する。MP4 track は valid per-track time base を持ち、
packet/chunk は PTS、DTS、duration の known/unknown と known zero を区別する。Chunk を経由する parser path も
timing を失わず、PCM parser は既知 sample timing を投影する。descriptor fingerprint、graph validation、Plan、
private runtime connection は timeline の有無を保持する。

### mapping と保存既定

M7-2 は explicit 1 input/1 output graph と明示 mapping だけを扱う。M7-3 の mapping を省略した path は
全 eligible track を Inspect order で map し、standard が Many terminal を自動生成する。明示 mapping は
exact input index、canonical `stream.ID`、output indexを持つ既存 `job.MapStream` に限定する。存在しない stream、
duplicate route、target に表せない明示 mapping は Planning error とする。同じ input track の複製は明示 mapping
のみ許可する。

無指定 path は format、codec、stream order、metadata/raw state を保持し、copy/remux を優先する。PCM Binding は
明示した変換または target requirement に必要な時だけ選ぶ。codec Binding のない video/subtitle/data track は
raw packet copy する。default preserve-all path で保持できないものがあれば、M7 では黙って drop せず Planning を
失敗させる。明示 mapping で選ばなかった track は user intent による除外である。

Plan は repeated descriptors、resolved exact mapping、copy/PCM decision、route ordinal、`SerialFanIn`
policy、MP4 の per-track sample-table reconstruction、I/O capability を表示する。
新しい selector DSL、per-edge solver、generic loss model は作らず、concrete logical connection を既存 solver へ
個別に渡す。

### MP4 I/O と exact boundary

M7 の MP4 input は RandomRead+StableSize、output は RandomWrite を要求し、単一 `mdat` の unfragmented mode だけを実装する。
複数 `mdat` は一つ目だけを使う等の silent fallback をせず unsupported とする。将来の multi-`mdat` 対応は、sample location を
constant-RAM で扱う bounded disk index/scratch consumer とともに拡張する。
source/sink capability と選択 mode は既存 Plan boundary へ残す。pure sequential/fragmented mode と output boundary
spool をこの slice の fallback にしない。内部の bounded re-scan と Host-owned disk table journal はこの境界と別である。
direct reader は provider carrier を先に全走査せず、sample payload と preservation range/table page を同じ borrowed
RandomRead Opening から必要な分だけ読む。Run の payload-heavy fixture では Prepare/Inspect 後に I/O counter をリセットし、
総 read bytes を source size の 1.25 倍以下に固定する。これは時間比ではなく I/O 量の gate であり、source 全走査が
復活して約 2 倍になる回帰を検出する。

unchanged same-format remux は selected sample payload、track ordinal、`Packet.Sequence`、PTS/DTS/duration、per-track
sample table、track/mapping order、preservable raw top-level/track box、sample entry、metadata carrier の byte 列と anchor 内相対順を
保持する。file byte identity、cross-track physical interleave、再生成する既知 box の全体順、offset、global DTS interleave は
exact に含めない。physical interleave の変更は semantic loss と扱わず、将来 `Stable`/byte reproducibility が必要なら execution
signature と別 ordered policy/backpressure を要求する。
raw/sample-entry state を再利用できるのは、単一 input の same-format inspection が同一 format mux の immutable
`CompileContext` へ渡され、Open 時に Host が元の source Opening を貸し出した場合だけである。複数 input から
provenance を推測しない。default preserve-all で安全に再利用できない場合は Planning error とし、推測して drop
または stale anchor を再利用しない。

### Queue policy

M5 の旧 `QueuePolicy.Window` が兼ねていた二つの意味を分ける。physical queue limit は stream-local span だけを制限する
`Span` とし、item/byte limit とともに buffer/Plan へ投影する。Zip の timestamp alignment tolerance は別の
Zip alignment field/Plan projection へ移す。同一 graph に Zip と `SerialFanIn` が共存しても、非ゼロの
`job.AlignmentPolicy.Zip` は Zip edge だけへ投影し、Serial edge の tolerance は 0 のままとする。
`SerialFanIn` は Zip alignment を使わず、cross-input availability や cross-track timestamp order を待たず、input ordinal を
保持して callback を一 item ずつ同期直列化する。Serial 実行へ非ゼロ tolerance を直接適用するのは runtime/internal error である。
late/drop/conceal policy は M9 の realtime consumer まで追加しない。

## core と plugin の責任境界

Core/Host/runtime は static `Spec.Ports` と execution binding の一致、descriptor cardinality/identity、route
ordinal、typed ownership、per-connection schema/time base、serial fan-in の input ordinal/EOF/cancel、mapping
cardinality を検証する。global timestamp order、cross-track timestamp comparison、MP4 sample-table 規格分類は core の
責務にしない。invalid plugin output で memory ownership や隣接 connection を壊させない。

Format/plugin は Inspect が実 file と一致すること、Inspection を shared immutable value として構築し実行中に
mutate しないこと、pure callback が global state を読まないこと、MP4 box/sample table/provenance が規格上正しい
ことを担う。Core は plugin の immutable 遵守、catalog access の不在、box 分類の正しさを reflection や sandbox で
証明しない。
これらは plugin conformance と規格 fixture で検査する。

## 作業単位と依存順

```text
M7-0 contract
  └─ M7-1 static multi-stream execution
       └─ M7-2 unfragmented MP4 reader/writer/remux
            └─ M7-3 default/exact mapping and PCM binding
                 └─ M7-4 conformance/integration/performance completion
```

### M7-1: static multi-stream execution

Make `Spec.Ports` the sole executable topology, remove dynamic Shape/ShapeContext, keep Format-specific inspection as a
shared immutable value outside the generic trait store, and expand repeated descriptors into private logical-to-physical typed
connections. The typed Router and this connection expansion are implemented and reviewed. M7-1 is complete, including
the selected `Batch`/`Joiner + SerialFanIn` execution. `SerialFanIn` retains input ordinal and synchronously serializes
callback invocation one item at a time; it is not an ordering algorithm and does not promise concurrent producer
wall-clock order or reproducibility. Queue `Span` remains separate from Zip alignment.

### M7-2: unfragmented MP4 remux

M7-2 starts with the narrow same-format shared immutable `Inspection` handoff, followed by the MP4 parser/Inspect path.
Implement the explicit 1 input/1 output MP4 graph, single-`mdat` MP4 Probe/Inspect, RandomRead+StableSize packetized demux,
RandomWrite unfragmented mux, direct-island emit-call-order mdat writing, and per-track sample-table reconstruction from
track ordinal, `Packet.Sequence`, PTS/DTS/duration. Inspection may contain only format-owned ranges and bounded summaries;
every Inspect `ReadAt` is pre-charged and table scans use fixed pages. At Open the Host lends the original source Opening to lazy
cursors without carrying the Inspect budget forward. The demux is a direct `RoutedReader`: the Access provider remains the input
Boundary identity but no provider carrier node/edge is generated, and one acquired session/Opening is shared with the same-format mux.
Automatic no-graph MP4 fixes the direct reader and writer, then creates the no-map preserve-all Many mapping before solver evaluation.
When an unfragmented transform mux must accumulate table state, it declares
a fixed `Compiled.Scratch` claim and uses its borrowed node-local journal under the aggregate `ScratchMaxBytes` ceiling. Complete
only when multiple `mdat` is rejected as unsupported, PCM plus unknown video/subtitle/data tracks roundtrip without decode, and
default raw state is exact or Planning fails.
Global timestamp interleave, cross-track timestamp comparison, public time-ordered merger policy, cross-input waiting merge, and
cross-track physical interleave reproducibility are not M7-2 deliverables. Physical interleave changes are not semantic loss; a future
Stable/byte-reproducible consumer must add an execution signature and ordered policy/backpressure.

### M7-3: mapping and PCM Binding

Standard automatic no-map 1×1 preserve-all fixes direct reader/writer nodes and passes their ordered repeated descriptors
through the existing solver as a whole. It projects repeated descriptors/mapping/decisions to Plan and selects PCM codec
paths only when required. Explicit `job.MapStream` remains the exact mapping surface; route-specific Many bridge search
stays fail-closed until it has a concrete consumer. M7-2's explicit graph remains the prerequisite.

### M7-4: completion verification

Extend public testkit and integration without an MP4-only private path. Cover unfragmented multi-track files,
per-track timescales, unknown video/subtitle/data, unknown boxes/sample entries, exact/default mapping, cancel/EOF,
ownership, and performance. Required conformance must not be silently skipped.

## 延期する consumer

| capability | earliest owner | consumer required before API |
|---|---|---|
| MP4 `ilst` mapping、generic loss DTO、strict metadata | M8 | migrated metadata encoding that needs structured predicted/actual loss |
| finite graph seek、preroll/reset/result | M8 | MP4 plus migrated MP3/FLAC/decoder path |
| rich selector syntax/language/disposition surface | M9 | CLI/WASM/HTTP or multi-input/output surface |
| pure sequential/fragmented MP4、sequential-output boundary spool alternative | M9 | stdin/stdout、remote or streaming surface |
| late/drop/conceal/realtime alignment | M9 | Endpoint clock/live consumer |
| cross-stream time-ordered fan-in for another container | M9 | 実 consumer と現実的な backpressure policy |

延期項目は M7 API へ placeholder field、empty DTO、unused policy として先行追加しない。

## Performance gate

M7 fast path は `MP4 direct demux → per-track copy or typed PCM path → SerialFanIn → MP4 mux` である。Serial input buffer のない
direct な single synchronous execution island では単一 routed producer の emit call 順を physical order として扱うが、route table、
mapping、descriptor connection は Open 前に作り、Run は typed closure/ordinal と到着した一 item だけを使う。

[performance](performance.md#開発時の性能回帰方針) に従い、同一 process/fixture で Router/RoutedReader と SerialFanIn を含む
unchanged multi-track remux と PCM-bound path を AB/BA 測定し、Open と steady-state Run を分けて `-benchmem` を取る。
Router と SerialFanIn orchestration の per-item mandatory allocation は 0 とする。buffer/fan-out/concurrent producer の
cross-track physical interleave は correctness/performance gate の契約にせず、`buffer.Handle.Range` 等の
payload slicing control allocation は literal zero の gate に含めず、user-visible time または無視できない allocation
が概ね 2 倍以上悪化した時だけ paired profile で調査する。

constant-RAM/resource gate は 1,000 samples と 1,000,000 samples の同一 topology/descriptor/queue/page/semantic-metadata
caps を比較する。Inspect、Compile、Open の peak live heap と retained object 数は sample 数、duration、opaque raw payload
長に比例して増加してはならず、opaque data は range/page copy のままにする。sample table の増加分は許可された
Host-owned disk table journal の bytes として計上し、`ScratchMaxBytes` の aggregate quota を越える前に deterministic に失敗させる。WAVE
unknown chunk/trailer も同じ source-range gate を通す。1k/1M の処理時間が比例すること自体は failure とせず、heap の
sample-count growth、raw payload の全量保持、journal quota 無視、または同一条件で概ね 2 倍を超える steady-state
allocation/item を failure とする。output boundary spool をこの gate の table journal として代用しない。
さらに payload-heavy fixture の Run だけを数え、RandomRead bytes を source size の 1.25 倍以下に固定する。Prepare/Inspect
の byte 数と wall-clock はこの gate に混ぜず、provider carrier の全走査が戻って約 2 倍になる回帰を I/O 量で検出する。

## M7 completion conditions

- M7-C01〜M7-C12 が production consumer と negative case を持つ。
- `standard.NewHost()` で単一 `mdat` の unfragmented RandomRead+StableSize/RandomWrite MP4→MP4 default remux、exact `MapStream`、
  PCM Binding、unknown video/subtitle/data raw copy が実行できる。
- Plan が ordered repeated descriptors、resolved mapping、copy/PCM decision、route ordinal、`SerialFanIn`
  policy、per-track sample-table reconstruction、I/O capability を示す。
- default preserve-all は selected sample/timing/order/raw provenance を黙って失わず、保持不能なら Planning error になる。
- Inspection は shared immutable で clone/I/O handle/raw byte/O(samples) array を持たず、全 Inspect `ReadAt` を事前課金する。
  WAVE unknown chunk/trailer は source range、semantic metadata は明示 cap、transform mux の table state は固定 node claim と
  aggregate `ScratchMaxBytes` の内側にある Host-owned disk journal で扱う。
- 1,000/1,000,000 samples の resource gate が constant-RAM、bounded page、journal quota、boundary spool との区別を確認する。
- conformance corpus、full module test、generator、docs check、performance gate が green である。
