# M7-0: multi-stream contract

> M7 の実装前に、MP4 を最初の実 consumer とする multi-stream execution の公開境界、
> product semantics、検証責務を固定する。この文書は M7 の固有完了条件と R-17
> traceability の正本である。実装順は [M7-0 作業単位](#作業単位と依存順)、個別の
> package 実装はそれぞれの unit に従う。

## 目的と境界

M7 は、有限・static な MP4 file-to-file job において複数 track の mapping、保存優先の
copy/remux、PCM audio の Binding、未 decode video/subtitle の raw stream copy、metadata
mapping/loss report、seek を通す milestone である。MP4 はここで作る execution contract の
唯一の公式 consumer であり、general purpose の media role registry を導入する理由ではない。

対象外は video/subtitle frame の decode/encode、MP3/FLAC と audio processor の移行、live
dynamic topology、Endpoint/clock、stdin/stdout、WASM、`_legacy/` の削除である。MP4 が構造的に
扱える data/attachment/未知 handler track は raw copy の対象に含めるが、decode/transcode の
対象にはしない。

M7-0 自体は文書と contract の確定 unit である。`plugin/mp4`、新しい production export、
format family の移植は下記の実装 unit で初めて追加する。実 consumer のない API を M7-0
だけで追加しない。

## 確定した product semantics

### inspection、topology、Shape

Format selection と Inspect の後に、Host は immutable な inspected topology を作る。各 track は
canonical `stream.ID`、open schema ID、optional timeline、property、metadata、format-specific
raw/sample-entry state を持つ。`stream.ID` は format が Inspect 時に採番する opaque identity であり、
Host、CLI、plugin が文字列の構造を解釈しない。

`plugin.ShapeContext` は node-local prepared facts の read-only view を持つ。`format.InspectionOf`
相当の typed accessor は `ShapeContext` と `CompileContext` の両方で同じ prepared value を読む。
`Shape` は selected config と prepared facts だけの pure function であり、catalog、Access session、
output transaction、mutable global state を取得しない。Host は Inspect 前の仮 Shape で dynamic port を
検証してはならず、Inspect → topology/mapping resolution → Shape → Compile の順を守る。

MP4 demux は inspection-aware Shape で input の一つの byte port と、選ばれた track ごとの
packet output port を返す。port ID は Plan/debug 用の canonical control-plane valueであり、item
loop の dispatch key ではない。MP4 mux は同じ `codec.Packets()` の `Many` input port を一つ持ち、
resolved mapping order の input descriptors から output track table を作る。

### typed Router と Merger

`flow`/`plugin` は既存の one-in/one-out `Processor` と zip `Joiner` を拡張して、次の topology
primitive を持つ。

- `Router[I, O]` は一つの typed input から、同じ typed `O` を運ぶ inspection-derived な複数 output
  port へ item を送る。operator は Compile/Open 時に固定された route ordinal だけを使う。runtime が
  ordinal を typed delivery closure の slice に解決するため、item ごとの port string lookup、reflection、
  `any` transport はない。
- `Merger[I, O]` は同じ typed `I` の `Many` input を一つの ordered execution に集約する。各 input の
  descriptor と order key は Compile/Open 時に固定し、runtime は typed queue head だけを比較して一つを
  operator へ渡す。M7 の MP4 mux は packet DTS を key とする `Merger[packet.Packet, access.Write]` の
  consumer である。

これらは media kind を知る role ではなく、schema type を捕捉した execution topology である。任意の
heterogeneous port map、multiplexed `any` item、item による component selection は導入しない。通常の
source/processor/sink、fan-out、zip は既存の typed fast path のまま残る。

`MergeFanIn` は zip と別の意味である。merge は各 non-EOF input の head が得られるまで待機し、最小
DTS の head を一つだけ消費する。input が EOF になった後は残る input を drain する。DTS が無い、
rescale が overflow する、同一 stream の DTS が後退する場合は fail-closed にする。同時 DTS の順は
resolved mapping order、次に packet sequence の全順序とする。比較は queue head の選択時だけであり、
全 item の型消去や timestamp string 化を伴わない。

### identity、timeline、packet

stream identity は control plane の descriptor と compiled edge に属する。`packet.Chunk` と
`packet.Packet` に `stream.ID`、format name、selector を追加しない。packet/chunk は data plane であり、
`stream` の metadata/property/topology package を import してはならない。demux の route、parser/codec
path、mux の input ordinal が edge identity を保つ。

`stream.Descriptor` の timeline は optional にする。byte/access のように timeline を持たない schema は
placeholder time base を偽装しない。MP4 track は valid な per-track time base を持ち、packet/chunk は
PTS、DTS、duration を区別して保持する。`Chunk` を経由する Parser path でも decode time と duration を
落とさない。descriptor fingerprint、graph validation、Plan projection、runtime edge state は timeline の
有無を区別する。

### mapping と default

mapping は requested selector と resolved concrete mapping を分ける。selector は input choice、canonical
stream ID、open schema ID、language/disposition を表す format-specific typed property を組み合わせる。closed
な audio/video/subtitle enum や任意 predicate/function は Job に入れない。selector は Inspect 後に
canonical stream IDs へ deterministic に解決され、zero/many match は `optional` または `all` を明示した
selector 以外では Compile diagnostic になる。

map を指定せず output が一つだけの場合、入力が一つなら全 eligible track を Inspect order のままその
output へ map する。複数 input または複数 output で map を省略した job は ambiguity diagnostic とする。
explicit mapping の output order は resolved mapping に固定して Plan に出す。同じ input track を複数
output へ送ることは明示 mapping だけで許可し、fan-out の ownership contract を使う。

無指定の path は C4 に従い format、codec、stream、metadata を保持し、可能なら copy/remux を選ぶ。
codec Binding の無い track は raw packet/carrier として copy 可能であることを Plan に表示し、decode、
filter、codec change を要求した時だけ unsupported diagnostic にする。明示 selected track が target format
で表現不能な場合は Compile error とする。無指定の preservation path で output が表現できない場合だけ、
loss report を予測し strict metadata policy が無ければ warning とする。

### MP4 I/O、raw preservation、metadata

MP4 input は moov-first なら sequential read を許容する。moov-after-mdat、index/seek、または他の random
read を要する path は RandomRead を要求し、finite input で明示 `AllowSpool` と quota/storage がある時だけ
spool alternative を選ぶ。MP4 output は sequential sink には fragmented MP4 を選び、non-fragmented output
は RandomWrite を要求する。non-fragmented を明示要求して capability が足りない場合だけ、同じ明示 spool
policy を候補にする。preset は spool を暗黙に有効化しない。選択した mode、source/sink capability、spool
effect、quota は Plan に固定する。

unchanged same-format remux だけが input MP4 の raw top-level/track box、sample entry、metadata carrier を
preserve できる。mapping、sample entry、metadata、track topology を変更した anchor は再利用せず、保持不能
の raw block を origin、target、reason とともに loss report へ載せる。output mux に渡すのは、resolved
input inspection と mapping から作った narrow immutable remux provenance だけであり、Open に catalog や
general Host service を渡さない。

M7 は MP4 `ilst` metadata encoding を最小の実 encoding consumer とする。RIFF INFO と `ilst` の間では
declared `metadata.Mapping` だけを適用し、mapping decline、target に表現不能な entry、raw block の
非再利用を loss として残す。Plan は予測 loss、Result は実際に発生した loss を持つ。strict metadata
policy は Planning で予測可能な loss を error にし、runtime でのみ判明した loss は output commit 前に
job failure とする。RF64 reservation `JUNK` の B8 loss も同じ Result report の consumer にする。

### seek と exact boundary

seek は finite MP4 graph operation であり、Demuxer の optional method ではない。Plan は target timeline、
selected index/sample、actual start、per-track policy、decoder preroll、processor reset、event replay、output
timestamp policy を記録する。PCM track は target への exact sample start、raw video/subtitle/data track は
target 以下の最も近い sync sample から開始する。output timestamp は seek point を zero に rebase し、
actual start と requested target の差を Plan/Result に表示する。decode path が存在する場合の preroll と
filter warm-up は M8 以降に同じ graph operation へ追加する。

MP4 の lossless remux exact は file byte identity を意味しない。unchanged same-format MP4 → MP4 で、
selected sample payload、DTS/PTS/duration、track/mapping order、preservable `ilst` entry、anchor が維持される
unknown box/sample-entry byte 列と anchor 内の相対順が exact でなければならない。moov layout、offset、
interleave、再生成する既知 box の全体順、generated index、fragment boundary の再構成は許容する。変更、drop、mode conversion、spool により保持不能に
なったものは必ず loss report に現れ、黙った loss は許容しない。

### Queue policy

M5 の `QueuePolicy.Window` が兼ねていた物理的な queue span と media alignment tolerance を分離する。
queue policy は item/byte/stream-local physical span だけを制限する。名称を `Span` とし、schema が cheap
timing trait を持つ edge だけで有効にする。zip/window 等の alignment tolerance と late input の
wait/fail/drop/conceal は別の media synchronization policy とする。

M7 の MP4 DTS merge は alignment policy を使わない。有限 offline job として全 non-EOF input を待機し、
unknown/invalid order は failure とする。Fast/Stable/Portable は drop/conceal を選ばない。Realtime の
late/drop/conceal semantics は M9 の endpoint consumer まで追加しない。

## 作業単位と依存順

```text
M7-0 contract
  └─ M7-1 topology / dynamic execution
       ├─ M7-2 MP4 reader-writer / copy / I/O
       │    └─ M7-4 ilst mapping / loss
       └─ M7-3 selector / resolved mapping / default policy
            └─ M7-5 seek
M7-1 + M7-2 + M7-3 + M7-4 + M7-5
  └─ M7-6 testkit / integration / conformance / performance completion
```

### M7-1: inspected topology and typed execution

Implement inspection-aware ShapeContext, topology projection, optional timeline, packet/chunk timing completion,
typed Router/Merger binding and per-edge runtime descriptor state. Complete only when a fixture Router and Merger
use no erased item transport and multi-track MP4 Inspect makes the executable graph shape deterministic.

### M7-2: MP4 format, remux, and capability modes

Implement `plugin/mp4` Probe/Inspect, packetized demux, DTS merger-backed mux, raw/sample-entry preservation,
fragmented/non-fragmented alternatives and explicit spool. Complete only when PCM plus unknown video/subtitle/data
tracks remux without decode, and every mode selection or capability failure is explained by Plan/diagnostic.

### M7-3: mapping resolution and preservation default

Implement selector normalization, resolved mapping projection, per-edge bridge solving, default preservation and
explicit-map failure semantics. Complete only when a Host MP4 job deterministically maps every selected track and
does not open PCM decoder/encoder on an unchanged copy path.

### M7-4: `ilst`, mapping, and loss report

Implement the MP4 `ilst` encoding, declared RIFF INFO/`ilst` mapping selection, Plan prediction, Result report,
strict policy, and raw preservation loss. Complete only when unchanged raw data is exact, all intentional losses
are structured, and strict mode rejects each loss before a successful output commit.

### M7-5: seek operation

Implement finite MP4 seek planning/execution from `stbl`/`stss`. Complete only when PCM exact seek and raw-track
sync-point seek expose requested and actual start, rebase output timestamps, and execute reset/cleanup safely.

### M7-6: completion verification

Extend public testkit and integration without a MP4-only private test path. Complete only when the traceability
table is fully covered, the specification-derived MP4 vectors cover non-fragmented/fragmented, multiple tracks,
per-track timescale, unknown boxes, edit list, `ilst`, and the exact boundary, and required M7 conformance is not
silently skipped.

## Performance gate

The M7 fast path is `MP4 demux → per-track copy or typed codec path → DTS merge → MP4 mux`. It must not add
reflection, port/stream string lookup, `any` item transport, or a mandatory allocation/refcount hop to an item.
Control-plane maps, descriptor fingerprints, selector resolution, and route tables are created before Open; the
runtime retains typed closures and ordinals only. The DTS comparison may rescale queue heads with prevalidated
per-edge bases, but never scans or reformats every item.

Run a representative unchanged multi-track MP4 remux and PCM-bound MP4 path before accepting M7. Check allocs and
time under the same process/fixture conditions and treat an approximately 2x or greater regression as a failure
that requires investigation. Use paired benchmark/profile only when choosing between smaller differences. Correct
ordering, exact payload, ownership, cancellation, and bounded queues are correctness gates, not performance
trade-offs.

## M7 completion conditions

- M7-C01 through M7-C11 are covered by their listed production consumer and test; R-17 tableに未対応行がない。
- `standard.NewHost()` の MP4 composition で、multi-track MP4→MP4 default remux、PCM binding、unknown
  video/subtitle/data raw copy、explicit mapping、seek が executable である。
- Plan は resolved mapping、copy/transcode decision、DTS merge order、I/O mode/spool、predicted loss、seek
  plan を表示し、Result は actual loss と seek actual start を返す。
- MP4 exact boundary、metadata strictness、capability/spool failure、DTS failure、mapping ambiguity、cancel/
  Finalize/Commit cleanup を integration で確認する。
- M7 Tier 2 equivalent vectors と full module test、generator、docs check を実行し、performance gate に
  明白な回帰がない。

M7 に含めない video/subtitle frame type、audio processor、MP3/FLAC、live endpoint semantics、surface の
full selector syntax、`_legacy/` removal はそれぞれ M8/M9 の実 consumer まで追加しない。
