# M8-0: 公式 family 移行 contract

> M8 の公開境界、product semantics、M8-C01〜M8-C13 の traceability、sub-unit の依存順、固有完了条件を確定する。
> この文書を M8 固有完了条件の正本とする。

## 目的と境界

M8 は、M5 の切断で `_legacy/` へ隔離した公式 family を新 contract の上へ戻す。対象は PCM の全 sample 表現、
ADPCM/G.711、audio processor 17 種、ID3、Vorbis Comment、MP3、FLAC である。同時に、その移行が最初の実
consumer になる四つの横断機構 — typed sample vocabulary、metadata の多重度/Mapping/loss policy、variant
selection、graph seek — を確定する。公式 plugin 間の直接 import は composition の Binding へ移し、完了時に
`_legacy/` を削除する。

M8 に含めないものは stdin/stdout、WASM、demo web、rich stream selector、CLI の残り flag、descriptor から moov を
組み立てる汎用 MP4 mux（[B14](capability.md)）、pure fragmented/sequential MP4、output boundary spool、
device/session Endpoint、live dynamic topology、realtime alignment policy である。これらは M9 が surface と
同時に確定する。MP3 encoder と video/subtitle decode は公式 family の対象外であり、[延期する consumer](#延期する-consumer)
に置く。

### seek の扱いについての確認

着手前監査で、M0 baseline commit `4429711a` の MP3/FLAC demuxer が持つ `Seek(time.Duration)` に呼び出し元が
無いことを確認した。`core/node.Seeker` と `sdk/engine.SeekableDemuxerAdapter` は宣言されているが、pipeline、
CLI、WASM、demo web のいずれからも呼ばれていない。したがって「旧経路と同等以上の seek 能力」という
完了条件は、機構を作らなくても形式上は満たせる。この点を提起した上で、**roadmap の文面どおり完全な
graph seek を M8 で確定する**判断を採った。requester は M8 の library API（Host/Job）とし、CLI/WASM/web への
投影は M9 が担当する。[scope](scope.md#seek-と-live-topology) が列挙する 6 要素を一つの seek plan に記録し、
実行し、Result へ投影するところまでを M8 の範囲とする。

## 確定した product semantics

### typed sample vocabulary

現行 `media/sample` の `Format` は scalar 表現と packing を一つの enum に畳んでおり（`s16`/`s16p`/`f32p`）、
値を増やすたびに組み合わせが二乗で増える。`Layout` も `Mono`/`Stereo` を返す closed switch である。
`F32Planar` schema には consumer が無い。M8 はこれを直交した三つの軸へ分ける。

- **coding**: `u8`、`s8`、`s16`、`s24`、`s32`、`f32`、`f64`。wire 上の scalar 表現である。
- **packing**: interleaved か planar か。wire は interleaved、decoded frame は planar を canonical とする。
- **endian**: interleaved wire だけが持つ。planar typed frame は Go の scalar 型が値を決めるため `none`。

decoded frame の canonical schema は Go の scalar 型ごとに一つとし、`S16`（`int16`）、`S32`（`int32`）、
`F32`（`float32`）、`F64`（`float64`）の四つに固定する。有効 bit 深度は frame ではなく descriptor property の
`ValidBits` が持つ。8/16 bit wire は `S16`、24/32 bit wire は `S32`、float wire はそれぞれ同名の schema へ
decode する。schema を跨ぐ変換は明示 Converter component が担い、`Effect` として Plan へ出る。

`Layout` は channel 位置の集合を表す comparable な値型にし、WAVE の `dwChannelMask` と往復できるようにする。
位置が不明な N channel も表現でき、`Mono`/`Stereo` は名前付き定数としてその上に載る。channel 数だけを持つ
closed enum には戻さない。

同じ codec が複数の decoded schema を出せる場合、port schema は static なので component を分ける。
`Spec.Ports` が唯一の topology という [M7-C01](m7-0.md) の contract は変えない。

### codec Binding と family 間の依存方向

`plugin/wave` は `plugin/pcm`、`plugin/mp3` のいずれも import しない。WAVE の format tag と codec の対応は
`standard` の composition が `codec.Bind` で宣言する。同様に MP3 の先頭/末尾 tag area と ID3、FLAC の
`VORBIS_COMMENT` block と Vorbis Comment、MP4 の `ilst` と iTunes metadata encoding は `metadata.Bind` が
接続する。WAVE が `wFormatTag = 0x0055` で MP3 を運ぶ経路は、format と codec が互いを知らないまま
composition だけで解決できることの gate として扱う。

codec tag が絞るのは codec/parser の選択だけであり、[C4](decisions.md) の copy/remux 既定は変えない。

### metadata の多重度、Mapping、loss policy

[media](media.md) が M8 へ送った「`Values` と `First` の両方を全 key に提供し続けるか」を次のように確定する。

**多重度は key ではなく encoding が持つ。** `metadata.Document` は常に順序付きの複数値を保持する。key
vocabulary は規格ごとの制約を持たない。marshal する encoding が自分の規格上の多重度へ畳み込み、畳み込みで
失われた値を loss として報告する。ID3v2.4 text frame の複数値や `COMM`/`USLT` の language/description、
Vorbis Comment と RIFF INFO の繰り返し key、`ilst` の単一値が、同じ Document から矛盾なく書けるのはこの形だけである。
RIFF INFO は重複値を順序どおり保持して書き出す。

`metadata.Mapping` は M3 で宣言してから production consumer が無かった。M8-4 でその consumer を作る。
出力 carrier の encoding が Document の key を直接表現できない時に限り、宣言済み Mapping を適用する。
推測はしない。適用した Mapping の `Lossiness` は loss report に残る。
projection は source entry ごとに一度だけ行う。encoding が直接表現できる key は不変に保ち、残りは同じ source の
候補を priority、lossiness、target key ID の順で選ぶ。複数の source entry が同じ target へ変換された場合も、
順序付き複数値のまま encoding へ渡す。

loss policy は [C10](decisions.md) の確定判断に従う。既定は warning と loss report、strict は opt-in の
failure とする。Plan は planning 時点で分かる **predicted loss** を、Result は実行後の **actual loss** を持ち、
両者を同じ型で混同しない。

`Document` の block は source anchor と opaque payload を明示して区別する。entry の `Origin` は完全に空、または
carrier/encoding/block が一致する同一 Document 内の source anchor を指す完全な値だけである。opaque payload は
Origin から参照できず、同じ format owner が理解できるものだけを byte exact に保持する。foreign opaque payload は
target owner が error で拒否し、黙って落とさない。`Substituted` を含む lossy report は warning と strict policy の
対象であり、`Converted` かつ `Lossless` の report だけが policy 上 non-lossy である。

`metadata.Blob.Slice` は immutable な backing を共有する zero-copy の部分 Blob であり、ID3 の opaque frame と artwork
payload を全体コピーせずに保持する。入力 size の上限は encoding ではなく carrier owner が read 前に判断する。MP4 owner は
既知の `ilst.payloadSize` を retained Blob 分として read 前に job の movie budget へ reserve し、正当な large file は library
job budget を増やして扱える。不足や runtime range overflow は format invalid への縮退ではなく `Inspect` の `ErrUnsupported`
として返し、確定済み envelope の payload read が `InspectBytes` を超える場合も同じ扱いにする。in-process parser は returned
immutable `Document` を入力に対して現実的に linear に保持し、
大きな source/opaque bytes は `ParseContext.Payload` の Blob/Slice backing を共有する。Encoding は size cap/config や heap
estimator を持たず、不釣り合いな hidden allocation は plugin bug である。`InspectMemory` は任意の Go heap sandbox ではない。
M8-5 の MP3 carrier も tag body を読む前に owner 側の budget gate を行い、ID3 encoding 自身は size cap や config を持たない。

Vorbis Comment encoding が扱うのは FLAC `VORBIS_COMMENT` block payload だけであり、FLAC metadata block の size 上限は
FLAC owner、Ogg packet/framing bit は Ogg owner が扱う。vendor string は semantic `Encoder` ではなく owner 限定 raw
block として source edit に保持し、fresh output は `godexture/godec` を書く。`CONTACT`、`PERFORMER`、未知 field と
`WAVEFORMATEXTENSIBLE_CHANNEL_MASK` は raw のまま保持する。channel mask を semantic にする判断は FLAC consumer が現れる
M8-6 へ送る。`METADATA_BLOCK_PICTURE` は strict base64 と FLAC PICTURE body を通る binary image だけを semantic picture に
し、URI picture と qualifier を失う field は raw に残す。

### variant selection

`plugin.Contract` の `Platform` と `plan.Platform` は M4/M5 で入っているが、solver はそれを hard filter に
使うだけで、`plan.Node.Variant` は常に `identity + "#default"` である。M8-7 で実 SIMD kernel が入るときに
次を確定する。

- component は自分が持つ variant を宣言し、`Compile` が `CompileContext` の immutable platform snapshot から
  一つを選んで `Compiled` に固定する。選択結果は `Plan.Node.Variant` と execution fingerprint に出る。
- item loop は CPU feature も環境変数も読まない。選ばれた function は Compile/Open 時に確定する。
- `GODEC_FORCE_SCALAR` は `tools/cmd/differential` の process input に限定し、利用者向け runtime policy に
  しない。`dsp.HasAVX2()` のような package-level 判定を Program selection の代用にしない。
- variant は exact、bounded、semantic-only のいずれかを宣言する。整数 PCM の pack/unpack のように scalar と
  bit-exact な SIMD を `Fast` 専用にしない。

### graph seek

seek は Demuxer の optional method ではなく graph operation である。M8-8 は一つの seek plan へ次を記録し、
実行し、Result へ投影する。

- target timeline と domain
- source の index/keyframe point（MP4 `stss`/`stbl`、MP3 Xing/VBRI TOC と bitrate 推定、FLAC seektable）
- decoder preroll（MP3 の bit reservoir、FLAC の frame 境界、MP4 の sync sample）
- processor reset/warm-up
- metadata/event replay
- output/device clock reset

source が random access capability を持たない場合、seek は capability 不足の structured diagnostic になる。
黙って先頭から読み飛ばす fallback を既定にしない。到達した実位置は要求位置と異なりうるため、Result が
実位置を持つ。

### 明示 schema の登録負担

[config](config.md#schema) は「field ごとに ID、typed accessor、codec の 3 点を書く明示 schema が、17 processor や
FLAC encoder config で数百行になる」ことを M8 の判断事項として送った。M8-3 は 17 processor のうち field 数の
多いもの（equalizer、compressor、reverb）を先に明示 schema で書き、登録行数を実測してから adaptor の要否を
決める。作らない場合は理由を [capability](capability.md) へ記録する。struct tag を schema の主契約にしない
という [config](config.md) の原則は変えない。

### MP4 の受理範囲

[B11](capability.md)/[B12](capability.md)/[F58](findings.md) を M8-9 で次のように決める。

- 全 track を保つ remux は入力を byte 単位で再現するため、`mdia`/`minf`/`stbl` の未知 child box と、sample
  table が指さない `mdat` 内の byte を、format-owned な source range として保持したまま通す。
- track subset の remux は moov を作り直すので、sample の意味を変えうる未知 box（`sgpd`/`sbgp`/`saiz`/`saio`/
  `subs` 等）を含む track を選ぶ場合は fail closed のまま維持する。
- decode 経路は、sample 解釈を変えうる box を持つ track に対して fail closed を維持する。
- 判定は plugin 内で閉じ、[B15](capability.md) と同じく Compile の layout 検査と Process の着地位置検査の
  両方で確認する。

## core と plugin の責任境界

Core/Host/runtime は sample descriptor の property 整合、schema 一致、converter 挿入の必要性判定、Binding の
衝突検出、variant の platform 適合、seek plan の構造検証、loss policy の適用を担う。規格上の pack/unpack、
huffman/LPC/rice、apodization、TOC 補間、tag encoding、box 分類は plugin の責務であり、core は reflection や
sandbox でそれを証明しない。conformance corpus と規格 fixture が検査する。

metadata の多重度の畳み込みは encoding が行う。Host は「畳み込んだ結果と元の Document の差」を loss として
受け取るだけで、規格ごとの多重度規則を持たない。

## 作業単位と依存順

```text
M8-0 contract
  └─ M8-1 typed sample vocabulary
       └─ M8-2 PCM family completion (ADPCM, G.711, WAVE tags)
            └─ M8-3 audio processor family
                 └─ M8-4 metadata encodings and loss policy
                      └─ M8-5 MP3 family
                           └─ M8-6 FLAC family
                                └─ M8-7 variant selection and sdk placement
                                     └─ M8-8 graph seek
                                          └─ M8-9 completion and _legacy removal
```

### M8-1: typed sample vocabulary

`media/sample` の coding/packing/endian を直交させ、`Layout` を channel 位置集合にし、decoded frame の canonical
schema を四つ用意する。既存の WAVE/PCM/MP4 経路をこの vocabulary へ移し、8/24/32 bit と float、3 channel 以上を
通す。linear PCM の pack/unpack は coding ごとの分岐が一度だけ済む形にし、item loop から format switch を外す。
converter component をこの単位で入れ、schema 間変換の consumer を最初に作る。

### M8-2: PCM family completion

`plugin/pcm` に ADPCM (IMA, MS) と G.711 (A-law, μ-law) を戻す。WAVE の `wFormatTag` と codec の対応は
`standard` の composition が宣言し、`plugin/wave` は codec package を import しない。ADPCM の block 構造と
G.711 の table は `_legacy/` からではなく現在地の `plugin/pcm/internal` を使う。WAVE が MP3 を運ぶ tag は
M8-5 の後に binding を足す。

### M8-3: audio processor family

`plugin/audio` の 17 processor を typed `audio.Frame` の Processor として戻す。filter は sample format を
decode/encode せず、planner が region 境界へ converter を置く。exclusive frame は in-place、共有 branch は COW。
config は typed schema とし、生成 option を復活させない。mixer/convolver の multi-input は Compile と fan-in
policy で time base/layout/PTS を解決する。field 数の多い schema の登録負担を実測し、adaptor の要否を決める。

**実装で確定した訂正**（[M8-3 の確定事項](#m8-3-の確定事項)に詳細）。上の「mixer/convolver の multi-input は
fan-in policy で解決する」のうち convolver 分は撤回した。impulse response を signal と同じ Many port の ordinal
に置くと planner が bridge を挿せないため（bridge は incoming edge がちょうど 1 本の port にしか入らない）、
IR は独立した単一 edge の port とし、順序は `flow.Prior()` の宣言で表す。あわせて mixer は N入力×M出力の
matrix ではなく N→1 とする。

### M8-4: metadata encodings and loss policy

`plugin/id3`、`plugin/vorbiscomment` を戻し、MP4 の `ilst` encoding を `plugin/mp4` の別 component として足す。
Document の多重度を確定し、encoding 側に畳み込みと loss 報告を持たせる。`metadata.Mapping` の適用経路と、
predicted/actual loss、strict policy を入れる。

`ilst` component は MP4 container から独立して、外側の `ilst` box を含まない iTunes item atom 列だけを読む。
既知 item は Document の semantic entry に、解釈不能な item は owner 限定の opaque block に分ける。source が不変なら
item 列を byte exact に返し、編集時は変更した既知 item だけを canonical にし、opaque sibling は元の位置で保持する。
MP4 carrier への Binding と file-level の inspect/mux は M8-4 で接続する。owner は既存の validated
`udta/meta/ilst` envelope の inspect/rewrite だけを扱い、新規 envelope の synthesis は M9 に残す。

### M8-5: MP3 family

`plugin/mp3` の format（framing、Xing/VBRI、probe、parser）と decoder（layer I/II/III）を戻す。先頭/末尾の
tag area は codec bitstream 側が carrier を宣言し、ID3 encoding が composition 経由で接続する。SIMD kernel は
scalar 実装で先に通し、variant 契約は M8-7 で足す。

### M8-6: FLAC family

`plugin/flac` の format（native stream、STREAMINFO、seektable、metadata block）と codec（decode/encode、LPC、
rice、mid/side、block split）を戻す。apodization を data 表現にし、worker 数が bitstream を変えないことを
確認する。lossless roundtrip exact と MD5 を gate にする。

### M8-7: variant selection and sdk placement

M8-2/M8-3/M8-5/M8-6 で scalar として通した kernel に SIMD variant を足し、variant 宣言と Compile 時選択、
Plan/fingerprint 投影、injected platform での test を確定する。あわせて `sdk/{bits,dsp,hash,parallel}` の
最終配置と `sdk/bits` の `production` tag の扱いを決める。

### M8-8: graph seek

seek plan の型、planner での構築、runtime での実行、Result への投影を入れる。index 実装は MP4、MP3、FLAC の
三つを consumer にする。capability 不足の source は structured diagnostic にする。

### M8-9: completion and `_legacy` removal

MP4 の受理範囲を広げ、capability 表を全行確認し、`_legacy/` を削除する。conformance corpus、full module test、
generator、docs check、performance gate を通す。


## M8-3 の確定事項

実装で確定した product 判断と、着手前の契約から変えた点を記録する。

**convolver の impulse response は独立した入力 port にした。** 当初の「fan-in policy で解決する」は、IR を signal
と同じ Many port の ordinal に置くことを意味していた。しかし planner が edge に bridge を挿せるのは
[gap.go](../../internal/graph/gap.go) が示すとおり incoming edge がちょうど 1 本の port だけなので、その形では
「別 rate で録音された IR を自動 resample する」ができない。IR を config data として持つ案も同じ理由で退けた
（negotiation の対象にならない）。したがって IR は単一 edge の port とし、「先に読み切る」は `flow.Prior()` の
port 宣言で表す。runtime は prior 入力が終わるまで他を読まないので、待つ側は queue が埋まって producer が
止まるだけであり、component は何も抱えない。両 branch が同じ node を共有する topology は planning error とする。

**mixer は N→1 にした。** 旧経路の N入力×M出力 matrix は、出力の複製が runtime の fan-out で得られる以上、
一つの component に二つの概念が同居していた。matrix は mixer を M 個並べれば表せるので表現力は落ちない。

**`ZipFanIn` の終端契約を直した。** 「一つの入力が EOF に達したら join 全体が終わる」を「終わった入力は batch
から抜け、全入力が終わったら join が終わる」に変えた。旧契約では fan-in の主用途が成立しない。production
consumer が無かったため回帰範囲も無い。absent cell の意味は joiner が決める（mixer は無音とみなす）。

**Job の単一境界制限を撤廃した。** [bind.go](../../internal/bind/bind.go) が入力/出力を 1 本に制限していたため、
2 file を読む graph は planning できなかった。境界が 1 本なら port 名は不要、複数なら各境界が `Input.WithPort`
で開放 port を名指す。sort 順への暗黙依存を作らないためである。あわせて「同一 format の inspected 入力が複数
ある writable Format」を error から「どれも継承しない」に変えた。出力はもはやどの入力でもないので、持ち越す
べき source range が存在しない。

**`stream` に optional duration を入れた。** fade の fade-out と trim の末尾判定が必要とする。property であって
field ではないのは、終わりを述べられない stream（live、書き込み途中）が普通に存在するためで、不在をゼロで
表さない。WAVE は 1 block = 1 sample frame の場合のみ述べ、MP4 は all-ones でない場合のみ述べる。sample 数を
変える stage（resample、retime interpolate）は restate し、convolver は withdraw する。

**node-local temporary を quota 型として `plugin.OpenServices` に公開した。** [access](access.md#spool-adaptor) が
M6 で「第二の consumer が現れた milestone で共通 service へ昇格させるかを決める」と保留した判断であり、
normalize / trim がその consumer である。`Compiled.Scratch`（予約・Compile 時に size が確定）と
`Compiled.Temporary`（quota・書いた分だけ課金）は別 field とし、Plan にも別々に投影する。既定 ceiling は
4 GiB、`TemporaryUnlimited` で撤廃でき、`Realtime` は無効のままとする。

**明示 schema の登録負担は adaptor を必要としなかった。** field 数が最多の 3 つで compressor 27 行 / 7 field、
gate 43 行 / 8 field、equalizer 31 行 / 6 field。1 field あたり 4〜5 行で、うち 2〜3 行は help と range である。
[config](config.md#schema) が想定した「数百行」には達しなかったため、tag 由来 adaptor は作らない。判断は
[capability](capability.md#挙動変更の記録) へ記録する。

## Performance gate

M8 の fast path は `demux → parser → decoder → converter → filter region → converter → encoder → mux` である。
[audio](audio.md#benchmark-contract) の benchmark contract を実 filter で実行し、次を確認する。

- compatible な N filter region の sample format conversion が入口/出口の最大二回で、N に比例しない。
- linear in-place chain の payload allocation/copy が filter 数に比例しない。
- fan-out なしの ownership transfer に atomic refcount increment が無い。
- Plan に conversion 数、selected sample schema、selected variant が出る。

[performance](performance.md#開発時の性能回帰方針) に従い、日常の確認は代表 case で「同一条件の処理時間または
無視できない allocation が概ね 2 倍以上に悪化する明白な回帰」の検出を目的とする。小さな差は gate にしない。
scalar/SIMD の採用判断だけは同一 process の paired benchmark で確認する。FLAC/MP3 の decode/encode は
conformance corpus の代表 case で throughput と allocation を記録し、baseline との raw timing 比較は行わない。

## M8 completion conditions

- M8-C01〜M8-C13 が production consumer と negative case を持つ。
- `standard.NewHost()` で WAVE/PCM の 8/16/24/32 bit・float・multichannel、ADPCM、G.711、MP3 decode、
  FLAC encode/decode、17 processor、ID3/Vorbis Comment/`ilst`/RIFF INFO の metadata が動く。
- 公式 plugin 間に直接 import が無く、format tag ↔ codec と carrier ↔ encoding が composition だけで解決する。
- filter region の conversion 回数が filter 数に比例しない。
- Plan が selected variant、conversion、seek plan、predicted loss を示し、Result が actual loss と実到達位置を示す。
- FLAC の lossless roundtrip が exact で、worker 数が bitstream を変えない。
- 各 family の Tier 2 conformance corpus が green である（[fixtures](fixtures.md#tier-2-conformance)）。
- [capability](capability.md) に `未定` 行が無く、全行が新経路の実装または記録された廃止判断を持つ。
- `_legacy/` が存在せず、`go build ./...` と `go test ./...` が新 stack だけを対象にしている。
- full module test、generator、docs check、performance gate が green である。
